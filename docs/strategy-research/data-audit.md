# 홈서버 데이터 점검 결과

2026-09-10 19:39~19:44 KST에 `ssh home`으로 접속해 `kiwoom_db`를 읽기 전용으로 조회했다. **보유 구간의 형식 품질은 양호하지만, 2015년부터의 전체 코스피 백테스트용 데이터로는 아직 인수할 수 없다.** 시장·상품 혼합, 시작 구간 부족, 과거 시장 및 기업행사 이력이 주요 보완점이다. 이 결론은 실측한 KRX 일봉과 종목 마스터에 한정하며 주·월·분봉 전체를 감사한 결과가 아니다.

삼성전자(005930), SK하이닉스(000660), KODEX 200(069500)의 최초 일봉은 모두 2023-05-11이다. 따라서 기존 대화의 “2015~2022년 대형주 위주 표본”이라는 해석은 근거가 부족하며 철회한다. “2023년 이후 전 종목 사용 가능”도 연초부터 완전한 커버라는 뜻으로 사용할 수 없다.

현재 비활성 종목 중 일봉 보유 종목은 94개다(시장 코드별 19+23+4+2+46). 비활성은 상장폐지와 동의어가 아니며, 94개가 모든 과거 상장폐지 종목을 포괄하는지도 확인되지 않았다. `stock_code`는 유일하지만 유효기간을 가진 시장·상품 이력 및 상장폐지일 전용 컬럼은 이번 스키마 점검에서 확인되지 않았다. 다른 저장소나 원자료에 존재할 가능성은 남아 있다.

## 형식 검사는 통과했지만 거래 가능성과 완전성은 별개다

전체 조정 일봉에서 다음 값을 집계했다.

| 검사 | 발견 수 | 해석 |
| --- | ---: | --- |
| OHLC NULL | 0 | 네 가격이 모두 존재 |
| OHLC 0 이하 | 0 | 일봉 표본에서는 가격 부호 변환 불필요 |
| 고가·저가 관계 위반 | 0 | 고가가 O/C/L보다 작거나 저가가 O/C/H보다 큰 사례 없음 |
| 거래량 NULL / 음수 | 0 / 0 | 단위와 정지 처리의 적정성까지 증명하지는 않음 |
| 거래대금 NULL | 0 | 금액 단위는 아직 미확정 |
| `(stock_id, trading_date, adjusted)` 중복 | 0 | 해당 유일 인덱스도 존재 |
| 종목 마스터 없는 가격 | 0 | 참조 연결 가능 |
| 내부 날짜 누락 후보 | 0 | 아래 대체 달력의 제한 범위에서만 통과 |

내부 누락 검사는 DB 전체에 나타난 KRX 날짜의 합집합을 대체 달력으로 사용하고, 각 종목의 최초~최종 관측 범위 안에서 비교했다. **전 종목에서 동시에 빠진 날짜, 관측 시작 이전·종료 이후 누락, 실제 거래소 달력과의 차이는 검출하지 못한다.** 거래량 0인 날짜를 보간하거나 무조건 삭제하지 않는다.

현재 상장일 이전 행의 상위 표본에는 코스닥 분류 종목들이 나타났다. 시장 이전 가능성을 시사하지만 이번 작업에서는 각 종목의 공식 이력을 대조하지 않았으므로 원인은 미확정이다. `listed_date`로 이전 가격을 자르거나 현 `market_name`을 과거에 그대로 적용하지 않는다.

`trade_amount` 예시는 2026-09-01 삼성전자에서 3,975,422이며 거래량은 15,319,615주, 종가는 261,000이다. 금액 스케일 확인 전에는 원화 거래대금 필터로 사용하지 않는다. 종가×거래량은 실제 일중 거래대금의 정확한 대체값이 아니며 조정가와 원거래량을 섞을 수도 있다.

## API와 DB를 실제로 대조했다

GET `/api/kiwoom/stocks/005930/ohlcv/daily`의 2026-09-01~09-10 응답은 7개 일봉이었다. 날짜·OHLC·거래량·거래대금이 같은 기간의 SQL 결과와 전부 일치했다. 이 결과는 한 종목·7일의 회귀 표본이며 전 종목 API 일치 보증은 아니다.

- 해당 GET의 OpenAPI 설명은 DB 조회 전용이며 수집 호출을 하지 않는다고 명시한다.
- 2025-01-01~2026-09-10 조회는 HTTP 400이었다. 응답은 400일 제한을 설명한다.
- `exchange=SOR`는 입력 검증에서 거절되었다. 실제 상태 코드는 [요약 JSON](evidence/summary.json)에 기록했다.
- POST 수집·refresh·동기화 API는 호출하지 않았다.
- 사용자 예시의 `s.code` 대신 실제 컬럼인 `s.stock_code`를 사용해야 한다.

## 재실행과 근거
