# `krx_lab`의 48개 전략과 실자료 백테스트 전환 계획

**목적과 판단:** 이 문서는 `krx_lab`에서 무엇을 시험하도록 만들어 두었는지와 실제 국내주식 데이터로 수익률을 계산하려면 무엇을 구현·검증해야 하는지 설명한다. **진입 12종 × 청산 4종의 48개 후보와 합성 입력의 실행 검사는 준비되어 있다. 실제 데이터 실행·전략 선정은 현재 차단 상태다.** ted-startup이 데이터를 수집·정정해 버전과 근거를 함께 전달하고, vectorbt가 입력 적격성 판단·전략 생성·백테스트·결과 검증을 맡는다. 이 문서는 실행 계획이며 실자료 성과나 투자 적합성을 보고하지 않는다. 기준일은 2026-09-18이다.

읽는 순서: 1절에서 후보의 의미를, 2절에서 합성 검증의 범위를, 3절에서 현재 실자료 차단의 원인을 확인한다. 4~5절은 팀별 책임과 차단 해제 순서·완료 기준이다. 수식과 실행 세부사항은 마지막의 기존 명세·코드 링크를 따른다.

## 1. 48개는 12개 진입 규칙과 4개 청산 규칙의 모든 조합이다

후보 ID는 `진입ID__청산ID`이다. 예를 들어 `CROSS_5_20__PCT_3_6`은 5일·20일 이동평균 교차로 진입을 판단하고, 신호일 종가의 3% 아래 손절·6% 위 목표를 사전에 정한다. 이들은 비교할 **가설 목록**이지 수익이 검증된 전략 목록이 아니다. 실제 ID와 조합은 [`config.py`](../../../research/krx_lab/config.py)의 `ENTRIES`, `EXITS`, `primary_runs`에 고정돼 있다.

진입 신호는 모두 완료된 일봉의 종가에서 판단한다. 공통으로 전일 거래량 100,000주 이상과 지표 준비 250봉을 요구한다. 아래 `C`는 해당 일 종가, `SMA`는 단순이동평균, `RSI`는 상대강도지수, `MACD`는 이동평균 수렴·확산 지표, `ATR`은 평균 진폭이다. 임계값의 등호·초기화는 [전략 명세](strategy-spec.md)와 [`strategies.py`](../../../research/krx_lab/strategies.py)를 따른다.

| 진입군 | 후보 ID 2개 | 신호의 핵심 조건 |
| --- | --- | --- |
| 이동평균 상향 교차 | `CROSS_5_20`, `CROSS_10_20` | 단기 SMA가 전일에는 SMA20 아래, 당일에는 위 |
| 신고가 돌파 | `BREAKOUT_20`, `BREAKOUT_60` | `C`가 직전 20일 또는 60일 종가 최고치 초과 |
| 상승 추세 중 조정 | `TREND_PULLBACK_3`, `TREND_PULLBACK_5` | `C>SMA60`이고 3일 수익률이 각각 −3% 또는 −5% 이하 |
| RSI 회복 | `RSI_REENTRY_30`, `RSI_REENTRY_40` | `C>SMA60`이고 RSI14가 각각 30 또는 40을 아래에서 상향 통과 |
| 볼린저 하단 회복 | `BOLLINGER_REENTRY_1_5`, `BOLLINGER_REENTRY_2` | `C>SMA60`이고 20일 하단밴드(`k=1.5` 또는 `2`)를 아래에서 상향 통과 |
| MACD 상향 교차 | `MACD_CROSS_SMA60`, `MACD_CROSS_SMA120` | `C>SMA60` 또는 `SMA120`이고 MACD가 신호선을 상향 통과 |

청산 기준 가격은 신호일 종가·ATR로 정한다. 매수 후 유리한 미래 가격을 보고 목표·손절을 다시 고르지 않는다. 아래는 **신호일에 정하는 계획 가격**이며, 원가격 단위 변환·호가 반올림·기업행사에 따른 계획 조정과 실제 체결은 별도 검증 대상이다.

| 청산 ID | 손절 계획 | 목표 계획 |
| --- | --- | --- |
| `PCT_3_6` | `0.97 × C` | `1.06 × C` |
| `PCT_5_10` | `0.95 × C` | `1.10 × C` |
| `ATR_1_5_3` | `C − 1.5 × ATR14` | `C + 3 × ATR14` |
| `ATR_2_4` | `C − 2 × ATR14` | `C + 4 × ATR14` |

공통 실행 계약은 신호일 `t` 마감 뒤 판단 → 다음 거래일 시가에서 조건을 충족할 때만 진입 시도 → 사전 손절·목표·최대 달력 1개월 만기로 청산이다. 같은 일봉에서 손절과 목표가 모두 닿으면 손절을 먼저 적용한다. 1억 원 공동 현금계좌, 최대 20개 슬롯, 외부 입출금 0, 정수주와 재투자를 가정한다. 상세한 시가 상한·갭·거래정지·만기 예외는 [전략 명세](strategy-spec.md)에 있다.

## 2. 합성 검증은 계산·장부 경로를 시험했으며 48개 실전 성과가 아니다

기본 계획은 **816개 논리 실행**이다. 48개 후보마다 개발 구간 2015~2019에 1개, 검증 구간 2020~2023의 각 연도에 비용·지연 4조건씩 16개를 계획한다. 검증 조건은 편도 가정비용 10·30·50bp(1bp는 0.01%)와 신호 뒤 진입 지연 1거래일, 그리고 30bp·2거래일 지연이다. 이 숫자는 계획 슬롯 수이며 실제 시장 데이터 실행 건수가 아니다. 후보 고정 뒤 배분·통제·비용·일봉 충돌 등을 보는 **별도 조건부 33슬롯**이 있어 전체 논리 계획은 849개다. [조건부 합성 검증 기록](conditional-results-2026-09-14.md)의 33개 성공은 실제 2024년 이후 잠금 구간이나 48개 후보의 수익성을 검증한 결과가 아니다.

현재 합성 회귀는 신호 수식과 미래 정보 차단, 시가 진입·갭·동봉 손절 우선·월 만기, 공동현금·정수주 장부, 기업행사·날짜별 **합성** 시장 프로필, 저장·중단 후 재개·원장 대조를 검사한다. [2026-09-13 실행 기록](implementation-and-results-2026-09-13.md)은 기본 후보의 합성 개발 48건과 **한 후보**의 검증 16건, 총 64건을 확인했다. [조건부 결과](conditional-results-2026-09-14.md)의 33건은 별도 합성 실험이다. **기본 816슬롯 전체를 합성 자료로 실행 완료했다거나 실자료 수익률을 얻었다고 해석하지 않는다.**

## 3. 실자료 차단은 한 줄의 안전장치가 아니라 입력·엔진·연구 단계의 여러 조건이다

| 현재 코드 지점 | 현재 동작 | 실자료 경로에 필요한 변화 |
| --- | --- | --- |
| [`snapshot.py`](../../../research/krx_lab/snapshot.py)·[`quality.py`](../../../research/krx_lab/quality.py) | 기존 추출은 KRX 수정가격과 **현재** 종목 메타데이터를 읽는다. 가격 정의·혼합 공급자와 역사 이력·비용이 확인되지 않으면 `BLOCKED` 또는 탐색 등급이다 | 시점별 종목·원가격/조정가격·계수·상태·공식 달력·출처 버전을 묶는 별도 실자료 입력 어댑터와 검사 |
| [`admission.py`](../../../research/krx_lab/admission.py)·[`contracts.py`](../../../research/krx_lab/contracts.py) | C1 형식·파일·기간의 **읽기 전용 검사**만 한다. 실제 자료는 검사 결과가 좋아도 실행 적격 등급으로 올리지 않는다 | 실자료 인수 기준과 근거별 PASS/BLOCKED 보고, 미해결 행의 명시적 격리 정책. `real_data_admitted` 한 필드만 바꿔 우회하지 않음 |
| [`runner.py`](../../../research/krx_lab/runner.py) | `run`은 `BLOCKED`와 합성 이외 등급을 막고, `run-delivery`는 REAL 입력을 `REAL_EXECUTION_NOT_ADMITTED`로 거절한다 | 인수 통과한 고정 revision만 별도 REAL 실행 경로로 연결하고 결과에 데이터·코드·설정·비용 해시 저장 |
| [`execution.py`](../../../research/krx_lab/execution.py)·[`market_model.py`](../../../research/krx_lab/market_model.py) | 합성 원가격·기업행사·프로필의 장부 동작은 검사됐지만 실제 국내시장 체결·비용을 승인한 모델은 없다 | 날짜·시장별 원가격, 호가·수수료·세금·슬리피지, 거래정지·상폐·기업행사·현금정산과 불확실 체결 처리 검증 |
| [`conditional_runner.py`](../../../research/krx_lab/conditional_runner.py)·[`lifecycle.py`](../../../research/krx_lab/lifecycle.py) | 후보 고정·후속 33슬롯·잠금 접근은 합성 전용 | 개발/검증 완료→후보 고정→현실 비용→미사용 기간 접근을 실자료 증거로 연결하는 별도 게이트 |

따라서 `runner.py`의 거절 조건만 삭제해도 기본 스냅샷의 수정가격을 정수주 원가격으로 체결하거나 합성 비용을 실제 비용으로 오인할 수 있다. 현재 `config.py`도 미검증 조정가격을 허용하는 우회 옵션과 v1 후보 목록 변경을 거절한다. 차단은 유지한 채 새 실자료 경로를 검증해야 한다.

## 4. ted-startup은 데이터를 전달하고 vectorbt는 백테스트 입력으로 검증한다

역할을 분리하되, 전달 상태와 사용 가능 판정을 같은 것으로 취급하지 않는다.

| 담당 | 맡을 일 | vectorbt가 확인할 결과 |
| --- | --- | --- |
| ted-startup | 수집·정정·재수집, 원천 파일 또는 응답의 보존, 데이터셋 ID·revision·변경 이력 제공 | 원가격/조정가격 OHLCV와 계수, 영구 종목 ID와 당시 상장·시장·상태, 기업행사·상폐, 공식 거래일, 자료별 원천·시간·해시 |
| vectorbt | 전달 데이터의 읽기 전용 검사, 불명확한 행·기간 차단, 신호·전략·체결·비용 모델, 결과 저장·원장 대조·선정 | 데이터 인수 보고서, 허용 구간·종목 목록, 고정 실험 manifest, 실행 장부와 독립 대조, 후보 선정 또는 `NO_SELECTION` |

필드·표본·변경 이력의 상세 기준은 [데이터 전달 명세](remediation-discovery-2026-09-14/delivery-spec.md)와 [C1~C4 계약](contracts-v1.md)에 있다. 수집·가격 정정·결측 채움은 vectorbt 실행기가 자동으로 하지 않는다. 데이터가 부족한 경우 해당 입력을 `BLOCKED`로 보고하고 ted-startup에 근거와 함께 되돌린다.

**2026년 9월 14일 이후는 별도 가격·세션 계약이 필요하다.** ted-startup의 `docs/research/krx-after-market-impact-2026-09-18.md`는 키움 KRX 일봉 종가가 애프터마켓 마지막 가격을 포함해 정규장 공식 종가와 다르다고 확인했다. ted-startup은 공식 종가 복원 컬럼과 signal 소비처의 1·2단계를 반영했지만 첫 정기 실행과 나머지 소비처 검증이 남아 있다. 이 기간 또는 NXT·애프터마켓 전략을 시험할 때는 신호 확정 시각·주문 가능한 시장/세션·체결 순서·시장별 비용을 먼저 정의한다. 현재 일봉 엔진이 복수 세션의 체결을 재현한다고 가정하지 않는다.

## 5. 실자료 실행을 여는 작업 순서와 통과 기준

아래는 **구현 제안**이다. 단계별 결과를 확인한 뒤 다음 단계로 진행한다. 첫 대상은 기존 48개 후보의 **2015~2023 KRX 일봉 개발·검증**으로 좁히고, 2024년 이후 잠금 구간과 2026년 새 세션은 분리한다. 2015-06-15 가격제한폭 변경 전후의 영향을 진입·체결에 따라 따로 기록한다. 이후 기간은 선행 결과를 보고 규칙을 고쳐 유리한 재시험을 하는 일을 막도록 접근 이력을 남긴다.

2026-09-18 현재 vectorbt는 2단계의 **준비 도구**인 `inspect-real`과 오프라인 REAL 형식 표본을 갖췄다. 이는 C1 입력의 문제와 근거 공백을 정리하는 검사이며, 실제 전달 데이터의 적격 판정이나 2단계 전체 완료는 아니다. [준비 작업 WBS](real-data-preparation-wbs-2026-09-18.md)의 100%는 이 도구 제작 범위에만 적용한다.

또한 [오프라인 준비 WBS](real-execution-offline-wbs-2026-09-18.md)에 따라 조정가격 신호 준비, KRX 일봉 프로필 사전 검사, 검증된 로컬 스냅샷의 기간·종목·열 선택 읽기를 구현했다. `prepare_real_signals`는 종목 ID와 연속 활성 구간별로 지표 이력을 분리하고, 빠진 거래일의 신호를 만들지 않는다. `precheck_real_daily_profile`은 C1로 확인할 수 없는 비용·시장 규칙·기업행사 계보를 `BLOCKED`로 보고한다. `load_snapshot_window`는 스냅샷 해시를 확인한 뒤 요청한 범위만 반환한다. 이 함수들은 **고정 표본·제한된 입력의 준비 도구**다. C1의 인라인 가격 전체를 메모리에 읽고 신호 프레임을 만들기 때문에 전체 KRX 규모의 처리량과 메모리 상한은 아직 검증되지 않았다. 데이터 인수, 실제 체결 모델, REAL 수익률 실행은 여전히 후속 단계다.

| 순서 | 담당·작업 | 다음 단계로 넘어가는 증거 |
| --- | --- | --- |
| 1 | ted-startup: 2015~2023 KRX 데이터와 원문·버전·원/조정 관계·기업행사·당시 종목/상태·달력·비용 근거 전달 | 고정 revision과 파일 해시·행 수·필드 정의·변경 내역; 대표 표본에서 원문→저장값 재현 |
| 2 | vectorbt: 읽기 전용 REAL 어댑터와 인수 검사 구현 | 중복·결측·비양수·상태 모순·시점 누설을 종목/날짜별로 기록; 미해결 값은 수익률 입력에서 차단; 통과 범위·제외 범위 보고 |
| 3 | vectorbt: 조정가격 신호와 원가격 주문의 변환, 기업행사·정지·상폐·공식 거래일·실제 비용/호가 모델 연결 | 소형 실자료 표본의 주문·현금·주수·기업행사 원장을 독립 계산과 대조; 미지원 사건은 조용히 무시하지 않고 실패 |
| 4 | vectorbt: REAL 개발·검증 runner를 합성과 분리해 구현 | 인수된 revision만 실행; 48개 후보의 예정·성공·실패·0거래 상태, 해시, 장부, 원장 대조와 재개 검증; 불인수 입력·변조·잠금 접근 거절 |
| 5 | vectorbt: 2015~2019 개발과 2020~2023 연도별 비용·지연 비교 후 후보 고정 | 사전 기준·벤치마크·비용·체결 민감도·결측 영향을 함께 보고하고 한 후보 또는 `NO_SELECTION` 기록. 그다음에만 현실 비용과 미사용 구간의 접근 조건을 별도 검토 |

**최소 첫 구현 범위:** 1~2단계가 끝나기 전에도 실자료 형식 어댑터와 부정 사례 회귀는 합성 고정 표본으로 개발할 수 있다. REAL 실행 허용은 2~4단계가 실제 전달 revision과 독립 원장 대조를 통과한 뒤에만 연다. 처음에는 한 종목·짧은 허용 구간의 보존식과 주문 시각을 검증하고, 통과 후 48개 배치로 확대한다. 실자료 실행이 가능해져도 전략 선정은 5단계까지 완료해야 한다.

## 6. 현재 사용할 수 있는 vectorbt 입력 점검 명령

`inspect-real`은 C1 형식의 REAL 데이터 전달 JSON과 연결 파일을 **읽기 전용**으로 검사하고, 기존 C1 검사 문제와 현재 계약으로 입증할 수 없는 근거를 JSON으로 기록한다. 이 결과는 항상 `BLOCKED`·`INSPECTION_ONLY`이며 실자료 수익률 실행 권한을 주지 않는다. 데이터 전달 폴더 안이나 기존 결과 파일 위에는 보고서를 쓰지 않는다.

```powershell
$deliveryRoot = 'C:\data\krx-revision'  # 실제 전달 폴더로 변경
$reportPath = 'C:\reports\krx-revision-inspection.json'  # 존재하지 않는 새 경로
.venv/Scripts/python.exe -X utf8 -m research.krx_lab inspect-real `
  --delivery (Join-Path $deliveryRoot 'delivery.json') `
  --root $deliveryRoot `
  --out $reportPath
```

입력은 기존 [C1 계약](contracts-v1.md)의 `delivery.json` 및 manifest에 기록한 파일이다. 출력의 `inspection.issues`는 형식·파일·가격/상태 검사 문제이고 `evidence_gaps`는 원문 표본 대조, 요청·변환 계보, 당시 종목/기업행사/달력 완전성, 실제 비용·장부 등 아직 증명되지 않은 항목이다. 명령이 실패하면 원본을 고치지 말고 오류와 데이터 버전을 보존해 원인을 확인한다. 검사 결과가 깨끗해도 `run-delivery`와 기본 `run`의 REAL 차단은 유지된다. DB와 네트워크 접속은 하지 않는다.
