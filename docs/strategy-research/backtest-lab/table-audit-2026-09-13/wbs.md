# PostgreSQL 백테스트 입력 검증 WBS

현재 백테스트가 읽는 가격·종목 테이블과 인수에 필요한 보조 자료를 읽기 전용으로 검증한다. 가격 범위는 2015-01-02~2023-12-31이며 2024년 이후 잠금 가격은 조회하지 않는다. 검증 보고 완료와 데이터 인수 통과는 별개다. 이 작업은 상위 [연구 WBS](../wbs.md)의 W02·W03 검증 하위 작업이며 실제 수익률 실행·DB 수정·재수집은 범위 밖이다.

진행률: **100%** · 완료 **5/5** · 남은 검증 작업: 없음. 데이터 인수는 `BLOCKED`이며 [보고서의 보완 자료](README.md)가 필요하다. 이는 전체 백테스트 프로젝트의 완료율이 아니다.

## 실행 원칙

- 핵심 SQL 작성과 코드·계약 검토는 독립 에이전트에 병렬 배정한다. 메인은 연결, 보조 자료 조회, 증거 저장과 결과 통합을 담당한다. 각 에이전트는 기본 모델을 사용하며 SQL 정확성과 데이터 인수 판단을 맡긴다.
- 기존 감사와 스냅샷은 보존하고 새 관측을 별도 경로에 저장한다. 조회에는 트랜잭션 읽기 전용, 오류 즉시 중단, 문장·잠금 시간 제한을 둔다.
- 진행률은 동일 가중치의 완료 항목 기준이다. 데이터 인수 실패도 근거 있는 검증 결과이며 실제 백테스트 실행 완료로 표현하지 않는다.

## 완료 증거와 검토 반영

- [보고서](README.md), [집계 검증 JSON](verification.json), `evidence/`에 실행 근거를 저장했다. 핵심 DB 집계는 약 34초에 완료됐고 주요 기존 집계와 일치했다. 자료 정확성·행별 동일성 인증은 아니다.
- table_contract_review가 실제 코드·데이터 계약과 최종 보고서·검산기를 독립 검토했다. audit_sql이 핵심 SQL을 작성하고 메인이 기간·출력 계약을 통합했으며, 보조 SQL은 audit_sql이 독립 검토했다.
- 완료 마커 false 허용을 수정했고 회귀 테스트 9개가 통과했다. 초기 여러 줄 JSON 파싱 실패 기록은 보존하고 수정 후 별도 디렉터리에서 성공했다.
- 최종 문서 검토의 세 지적(보조 테이블 수, 고아 가격 검사의 실제 0건 명시, 기존 계약의 심각도와 보완 순서 용어 구분)을 반영했다.
- `ruff check`, SQL/증거 해시·집계 교차 검산, 문서 링크 19개 및 새 소스 공백 검사를 통과했다. 원 stdout의 PostgreSQL 출력 공백은 원문 보존 대상이다.
- 변경은 새 감사 디렉터리에 한정했다. 기존 `AGENTS.md` 수정 및 `docs/work-management/` 파일을 보존했다. 제품 테스트·Rust·사이트 빌드·DB 쓰기·수익률 실행·푸시는 수행하지 않았다.
