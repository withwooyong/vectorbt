# PostgreSQL 백테스트 입력 검증: 현재는 인수 차단

**2015~2023년 백테스트에 사용할 PostgreSQL 입력을 재검증한 결과, 실제 수익률 실행에 투입할 수 없다(`BLOCKED`).** 가격 6,109,214행·4,025종목 중 453종목의 72,072행(1.1797%)이 OHLCV 규칙을 위반하고, 원가격·조정 의미와 역사 기업행사 자료가 부족하다. 키와 조인 무결성은 통과했지만 데이터 인수 통과를 뜻하지 않는다. 검증 관측 시각은 **2026-09-13 22:34~22:37 KST**, 가격 조회 범위는 **2015-01-02~2023-12-31**이며 실제 마지막 가격은 **2023-12-28**이다.

2024년 이후 가격은 조회하지 않았다. 보조 테이블의 전체 행 수·최초/최종 일자와 현재 종목 마스터는 가용성 확인용으로 조회했으며, 이후 구간의 기업행사 상세나 전략 성과를 분석하지 않았다. 원본 DB 수정·재수집·실제 백테스트는 실행하지 않았다. **검증 작업 완료와 데이터 보완 완료는 구분한다.**

먼저 테이블별 판정으로 사용 가능한 범위를 확인하고, 가격·종목·보조 자료의 근거를 읽으면 된다. 보완 순서는 차단을 해소할 입력을 정리하며, 마지막 재현 절차는 다음 수집 후 같은 검사를 반복하는 방법이다. 진행 상태는 [검증 WBS](wbs.md)에 있다.

## 1. 현재 사용하는 두 테이블과 다섯 보조 테이블의 판정

현재 추출 코드는 `kiwoom.stock_price_krx`와 `kiwoom.stock`만 직접 읽는다. 나머지는 원천·역사 자료를 검증하기 위한 후보이며, 테이블 존재를 실제 백테스트 연동 완료로 보지 않는다.

| DB / 테이블 | 역할 | 이번 실측·판정 |
| --- | --- | --- |
| kiwoom_db / `kiwoom.stock_price_krx` | 시가·고가·저가·종가·거래량(OHLCV) | **사용 차단**: 가격 규칙 위반 72,072행. 기간 내 전부 `adjusted=true`; 비수정 원가격과 조정 계보 미확보 |
| kiwoom_db / `kiwoom.stock` | 가격의 종목 ID→코드, 현재 시장·활성 상태 | **조인 키 통과, 역사 정보 미검증**: 마스터 5,011종목, 상장일 결측 504종목. 과거 거래 대상 판정에는 부족 |
| kiwoom_db / `kiwoom.raw_response` | 가격 원문과 변환 경로 대조 | **자료 부족**: `ka10081` 보관 0건. 본문은 조회하지 않음 |
| signal_db / `public.corporate_event` | 분할·병합·배당 등 기업행사 후보 | **대상 기간 자료 없음**: 결정일·효력일 기준 모두 0건 |
| signal_db / `public.dart_disclosure` | 기업행사 공시와 시점 근거 | **대상 기간 자료 없음**: 접수일 기준 0건 |
| signal_db / `public.dart_corp_mapping` | 현재 법인·종목 매핑 후보 | **현재 키 진단만 통과**: 3,654행·종목 코드/법인 코드 각각 3,654개. 과거 유효기간 필드 없음 |
| signal_db / `public.stock` | 현재 종목·업종 보조 후보 | **역사 정보에 부적합**: 4,312종목 중 업종 결측 4,307종목. 과거 유효기간 필드 없음 |

공식 거래일·종목별 거래정지/재개·날짜별 비용/호가 이력을 담은 전용 테이블은 조회한 `kiwoom` 및 `public` 테이블 목록에서 확인하지 못했다. 다른 스키마·외부 파일까지 없다고 입증한 것은 아니다. 이번에는 현재 추출에 쓰지 않는 signal DB `stock_price`, 분봉·주봉·월봉, 업종 지수 가격과 수급 테이블을 검증 범위에 넣지 않았다.

## 2. 키·조인은 정상이나 가격 의미와 값은 통과하지 못했다

가격 테이블을 종목 마스터와 조인하기 **전** 집계하고 조인 뒤와 대조했다. 고아 가격이 inner join에서 누락되어 검사를 빠져나가는지 점검했고, 이번에는 고아 가격이 없었다.

| 검사 | 실측 | 해석 |
| --- | ---: | --- |
| 원키 `(stock_id, trading_date, adjusted)` 중복 초과 행 | 0 | 해당 기간 키 무결성 통과 |
| 추출 코드 키 `(stock_code, trading_date, adjusted)` 중복 초과 행 | 0 | 현재 조인 결과 중복 없음 |
| 종목 마스터에 없는 가격 | 0 | 조인 누락 없음; 조인 전후 6,109,214행 동일 |
| OHLCV NULL, 음수 거래량, 비유한 값 | 각각 0 | 해당 형식 검사 통과. 실제 OHLCV 컬럼은 bigint |
| 주말 가격 행 | 0 | 주말 검사 통과. 공식 휴장일 검증은 아님 |
| 종목별 관측 시작~끝 사이 전체 관측일 기준 공백 후보 | 0 | 데이터 자체 날짜 집합 기준. 공식 달력·상장/정지 이력이 없어 완전성 인증 불가 |
| 시가·고가·저가·종가 중 0 이하인 행 | 63,852 | 아래 OHLC 관계 위반과 겹치므로 합산 금지 |
| 고가/저가와 다른 가격의 관계 위반 | 70,871 | 가격 규칙 위반. 원천·상태 원인 미확정 |
| 중복 제거한 OHLCV 규칙 위반 | **72,072 / 453종목** | 데이터 인수 차단 |
| 거래량 0 | 211,623 | 정지·비거래 여부 확인 대상. 자동 오류 판정 아님 |
| 거래대금 NULL / 음수 | 544,241 / 0 | NULL은 KRX 공급자 라벨 행 전부. 현재 추출 필드는 아니지만 거래대금 활용·체결 현실성 검증에는 보완 필요 |

공급자별 문제의 양상이 다르다. 아래 숫자는 DB의 공급자 **라벨** 기준이며 과거 수집 원천을 행마다 증명한 것이 아니다.

| 공급자 라벨 | 가격 행 | 종목 | 가격 규칙 위반 | 핵심 관측 |
| --- | ---: | ---: | ---: | --- |
| KIWOOM | 5,564,973 | 3,499 | 1,201 | 종목 `102950`의 종가 0 |
| KRX | 544,241 | 526 | 70,871 | 기존 고가<종가 오류 총계와 같음. 고가<종가이면서 거래량 양수 7,935행 |
| 합계 | 6,109,214 | 4,025 | 72,072 | 비정상 비율 1.1797% |

KRX에서 시가·고가·저가 0, 종가 양수, 거래량 0인 행은 62,647개다. 원천 표기·거래정지·변환 오류를 구분하기 전에는 전일 가격 채움이나 종목 전체 제외로 해결됐다고 판정하지 않는다. 이번 집계의 `nonpositive_ohlc`와 `inconsistent_ohlc`는 겹치는 규칙이며, 최종 비정상 건수는 별도 OR 조건으로 계산했다.

동일 종목·수정주가 상태 안에서 여러 공급자 라벨이 섞인 경우는 0개다. 그러나 **종목 간에는 두 공급자가 섞이며 조정 방식의 동일성은 미확인**이다. 전부 수정주가라는 플래그만으로 실제 정수주 수량·배당·분할 정산에 사용할 가격이라고 인정할 수 없다.

기존 19:28 감사와 공급자별 행 수, 비정상 OHLCV 총수, 종가 0 총수는 같았다. **행별 해시 동일성 또는 원천 정확성을 재검증한 결과는 아니다.** 비교는 [집계 검증 결과](verification.json)에 남겼다.

## 3. 현재 종목 마스터만으로 과거 거래 대상을 복원할 수 없다

`kiwoom.stock`의 ID 기본키·코드 고유키 및 가격 외래키는 확인했고, 코드·이름·시장 결측과 코드 앞뒤 공백은 0건이다. 현재 메타데이터와 가격의 날짜 관계는 별도 조사 대상이다.

- 현재 상장일 결측 **504종목**, 비활성 상태인데 상폐일 결측 **69종목**이다.
- 현재 기록된 상장일보다 앞선 가격이 **92,488행**이다. 코드 승계·재상장·현재 마스터의 기준일 문제를 대조해야 하며, 잘못된 가격 92,488행으로 단정하지 않는다.
- 상장일/상폐일 역전과 현재 상폐일 뒤 가격은 0건이다. 기존 조사에서 `delisted_date`가 마지막 수집 거래일 의미일 수 있다고 확인했으므로 이 비교만으로 상폐 처리 정확성을 입증하지 못한다.
- 현재 키 중복 0은 **과거 코드 재사용이나 코드 승계가 없었다는 증거가 아니다**. 당시 시장·상품 종류·업종·활성 상태의 유효기간 이력이 필요하다.

signal DB `public.stock`은 4,312종목이며, 업종 결측 4,307종목, 현재 DART 매핑 미연결 1,335종목이다. 두 DB 마스터의 행 수 차이는 모집단 차이일 수 있으며 행 단위 교차 대조는 하지 않았다. 현재 매핑 미연결도 상품 유형 등을 확인하기 전에는 오류로 확정하지 않는다. 숫자 6자리 형식 밖의 코드 75개는 형식 진단만 기록했고 오류로 분류하지 않았다.

## 4. 기업행사·공시는 2026년 자료만 있어 과거 인수 근거가 부족하다

실제 보관 기간을 조회해 이전에 스키마 후보로만 남았던 한계를 구체화했다. 날짜 범위는 내용 분석이 아닌 가용성 집계다.

| 테이블 | 전체 보관 행 | 보관 날짜 범위 | 2015~2023 대상 행 |
| --- | ---: | --- | ---: |
| `public.corporate_event` | 510 | 결정일 2026-06-01~2026-09-11 | 결정일 0, 효력일 0 |
| `public.dart_disclosure` | 56,100 | 접수일 2026-05-29~2026-09-11 | 0 |

대상 기간 기업행사가 없어 링크·중복·계수 결측 검사도 대상이 없다. SQL 결과의 0을 품질 PASS로 해석하지 않는다. 향후 자료가 들어오면 효력일과 당시 인지 가능 시점을 별도로 검사하고, 이벤트 종류별로 필요한 수량 계수·주당 금액·정산 근거를 적용해야 한다. `raw_payload` 컬럼의 존재도 원문 완전성이나 당시 보관을 보장하지 않는다.

## 5. 보완은 가격 원천과 역사 자료 두 갈래로 진행한다

현재 권장 순서는 아래와 같다. 자료 보완 요청의 내용을 정리한 것이며 원본 수정·수집 실행이나 타인에게 메시지 전송은 하지 않았다.

| 우선순위 | 필요한 산출물 | 해소할 차단과 완료 기준 |
| --- | --- | --- |
| 1순위 — 병렬 A | `102950` 종가 0 전후의 수정/비수정 원문; KRX 거래량 양수 고가<종가 및 OHL 0 표본 원 DataFrame·dtype | 원문→변환→저장의 값·단위·조정·반올림 재현. 과거 원문과 새 조회는 취득 시점·소급수정 가능성을 구분 |
| 1순위 — 병렬 B | 2015~2023 기업행사·상장/상폐·거래정지·코드 승계·당시 업종/상품 이력 | 영구 종목 ID와 효력일·인지 시점, 분할/병합·배당·상폐 보유분 정산 근거 확보 |
| 2순위 | 공식 거래일·가격/수량 계수·원가격, 실제 기간별 비용·호가 자료 | 기대 종목일과 비거래를 분리하고 정수주·현금·체결 모형에 맞는 입력 검증 |
| 3순위 | 수정 자료의 새 revision·스냅샷 및 동일 검증 재실행 | 원본·기존 실험을 보존하고 남은 오류·역사 계약의 해결 여부를 재판정 |

데이터가 보완되어도 소프트웨어 준비는 별도다. 현재 `runner.py`는 비합성 자료를 `ADJUSTED_SHARE_MODEL_NOT_VALIDATED`로 차단하고, 기업행사·역사 시장 모형 및 후속 실행 단계의 미완료가 남아 있다. 이번 작업에서는 실행 차단을 변경하지 않았다.

## 6. 재현 방법과 실제 검증 범위

실행은 저장소 루트의 기존 `.venv`와 `ssh home`을 사용한다. 외부 Python 패키지를 추가하지 않았으며 SQL은 모두 읽기 전용 트랜잭션, 문장/잠금 시간 제한, 오류 즉시 중단을 적용했다. 읽기 전용 설정이 서비스 부하 0을 뜻하지는 않는다. 핵심 가격 검사는 약 34초에 완료됐다.

아래 경로는 다음 실행용 예시다. 기존 출력 디렉터리가 있으면 스크립트가 거부하므로 새 이름을 사용한다. 날짜 범위는 검토된 SQL에 고정되어 있으며 잠금 구간을 자동 확장하지 않는다.

```powershell
.venv/Scripts/python.exe -X utf8 docs/strategy-research/backtest-lab/table-audit-2026-09-13/run_audit.py core --out "$env:LOCALAPPDATA/vectorbt-research/table-audit-next/core"
.venv/Scripts/python.exe -X utf8 docs/strategy-research/backtest-lab/table-audit-2026-09-13/run_audit.py inventory --out "$env:LOCALAPPDATA/vectorbt-research/table-audit-next/inventory"
.venv/Scripts/python.exe -X utf8 docs/strategy-research/backtest-lab/table-audit-2026-09-13/run_audit.py auxiliary --out "$env:LOCALAPPDATA/vectorbt-research/table-audit-next/auxiliary"

# 이번 저장된 증거의 해시·집계를 DB 재조회 없이 재검산
.venv/Scripts/python.exe -X utf8 docs/strategy-research/backtest-lab/table-audit-2026-09-13/verify_evidence.py
.venv/Scripts/python.exe -X utf8 docs/strategy-research/backtest-lab/table-audit-2026-09-13/test_run_audit.py -v
ruff check docs/strategy-research/backtest-lab/table-audit-2026-09-13
```

실행 증거는 SQL 사본, 원 stdout/stderr, 구조화 JSON, 시각·반환 코드·SHA-256 해시를 담은 receipt로 구성된다. 핵심·스키마·보조 검사는 각각의 일관된 트랜잭션이며 **두 DB를 하나의 동시 스냅샷으로 읽은 것은 아니다**. 서버의 6개 컨테이너는 연결 확인 당시 healthy였다.
