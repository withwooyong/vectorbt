# 006740 직접 증거 확보와 공급자 입력 연결 점검

**정정 본문·소각 실행·신주 발행 증거는 확보했지만 공급자 계수 입력에는 연결되지 않았다.** 006740은 공시 당시 영풍제지이며 조회 당시 DART 기업개황의 이름은 블루산업개발이다. 이번 문서는 2026-09-23 읽기 전용 점검을 보존한다. 직접 증거 확보와 계수·신호·실행 승인은 별개다.

원문·receipt·manifest·검증기는 공급자 저장소 `data/sources/006740-capital-evidence-2023/`에 보존했다. 원래 로컬 위치는 `C:/Users/aeby/vscode/ted-startup/data/sources/006740-capital-evidence-2023/`이다. 공개 브랜치는 `withwooyong/evidence-006740-handoff-20260923`이며 [공급자 증거 README](https://github.com/withwooyong/ted-startup/blob/withwooyong/evidence-006740-handoff-20260923/data/sources/006740-capital-evidence-2023/README.md)를 참조한다.

공개 복사본은 수신 receipt의 추적 쿠키 헤더 1건을 제거하고 manifest를 재해시했다. 공시 본문은 그대로이며 원래 로컬 묶음도 유지한다. 공개 manifest의 `publication`에 원래 해시를 기록했다.

검증기 `python -B verify_bundle.py`는 내부 28파일·기존 외부 참조 6개와 다섯 수량 등식을 검사한다. 외부 참조는 원래 로컬 절대 경로를 사용하므로 새 clone만으로 전체 검증이 완결되지 않는다. 7/12 보고서는 사후 완료 근거이며 4월 known-at으로 소급할 수 없다.

## 입력에는 여전히 원공시가 연결되어 있다

점검 기준 supplier HEAD는 `dec4fc1ab579ecbc7d1e1c06507f013a5be43473`, consumer HEAD는 `ceae86d46265095d898aaf9709087e41a2d4dc85`다. 이후 supplier `386b553`은 체결 승인 경로 설계 문서 변경이며 이 감사의 기준 시점과 구분한다.

1. `collect_ohlcv_allotment_disclosures.py`는 정정 공시를 후보에서 제외한다. 기존 수집 manifest는 원공시 `20230404003162`를 선택한다.
2. `parse_ohlcv_allotment_ratios.py`의 실제 파싱 행과 v2 후보도 원공시를 사용한다. `r=1.5`, `H=2.5`다.
3. `build_ohlcv_reference_factor_candidates.py` 및 `build_ohlcv_admitted_factors.py`는 기존 파싱·manifest를 소비한다. 새 증거 묶음을 읽는 연결은 없다.
4. v4 기업행사에는 권리락과 상장주식수 변동이 있으나 새 정정 증거 해시가 없다. `correction_history_scope=V4_MANIFEST_BOUND`는 새 직접 증거의 연결 증명이 아니다.
5. vectorbt preflight와 입력 어댑터는 기존 factor-admission-v2 및 audit를 소비한다. 공급자 신호 승인 보고서의 전역 true를 006740 거래량 승인으로 해석할 수 없다.

저장된 006740 v2 행은 가격 승인 true, 가격계수 `0.4301694915254237288135593220`, 거래량계수 null, 거래량·신호 승인 false다. 차단 코드는 `ALLOTMENT_RATIO_MISMATCH`, `VOLUME_TRANSFORMATION_NOT_DEFINED`, `VOLUME_UNIT_CHANGE_NOT_ESTABLISHED`다. 정정 후 r이 같아 H=2.5와 가격 역산값 약 2.32466509의 차이(약 7.5424%)도 남는다. 출처 교체만으로 0.5% 기준을 통과하지 않는다.

## 생성 이력의 최신성 한계

검사한 해시 연결 15개 중 9개는 일치했고 6개는 불일치했다. 후보·audit·manifest 등 저장 산출물 연결은 일치했으나 세 보고서의 정책 해시와 현재 정책, 파서·후보 생성기·계수 생성기의 현재 코드와 영수증 해시가 달랐다. 따라서 최신 코드로 재생성된 결과라고 주장하지 않는다. 기존 인수 보고서의 “현재 정책·해시 일치”는 해당 보고서 작성 시점 판단이다.

다음 단계는 공급자에서 새 입력 revision의 선택 공시·원문 해시·정정 체인을 명시하고, 당시 근거와 사후 완료 증거를 분리하는 것이다. 운영 DB 쓰기, 기존 봉인 v3/v4·정책 수정, 2024년 이후 가격 열람, 백테스트 실행은 이번 마무리 범위에 포함하지 않는다.
