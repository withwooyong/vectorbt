# SEALED v3 실자료 백테스트 실행 WBS

> **계획 이력:** 이 WBS의 업종 이력 차단과 기존 48개 기준은 같은 날 후속 결정으로 대체되었다. 현재 재개 기준은 [56개 실행 인수인계](handoff-v3-56-2026-09-21.md)와 [운영 DB 재점검](postgresql-readiness-2026-09-21/README.md)이다. 업종 25% 상한을 쓰지 않는 새 계약으로 구현하며, 아래 10%는 당시 계획 범위의 기록이다. 이번 보존 작업에서 실제 구현 진척을 올리지 않았다.

목적: ted-startup의 불변 revision `2014-2023-v3`를 vectorbt가 반복 가능한 로컬 자료로 인수하고, 제외 정책·현실 비용·체결·기업행사 검증을 통과한 제한 실행부터 실제 전략 배치까지 안전하게 연결한다. 현재 판단: ted-startup 공급은 완료됐지만 vectorbt의 최신 snapshot과 REAL 실행 권한은 아직 없으므로 구현과 검증을 진행한다. 범위: 2014년 워밍업과 2015-06-15~2023-12-31 KOSPI·KOSDAQ 보통주, 정규장 일봉, v3의 `REJECT`·`QUARANTINE` 계약. 한계: 2024년 이후 잠금 구간, NXT·애프터마켓, 업종 시점 전략, 라이브 주문은 포함하지 않는다.

진행률: **10%** · 완료 **1/6** · 남은 작업: snapshot, Gate A/B, REAL runner, smoke, 독립 검토 · 차단: 기존 48개 정식 비교에 필요한 시점별 업종 이력이 v3에 없음. 운영 DB는 읽기 전용으로만 사용한다.

## 판단과 검증 기록

- 선택·가정: ted-startup의 `2014-2023-v3`만 소비하고 v1·v2·기존 r3 Parquet은 실행 입력으로 승격하지 않는다. DB의 `REJECT`는 제외, `QUARANTINE`은 해당 범위·전략을 차단하며 임의 보정하지 않는다.
- 병렬 배정: v3 adapter 설계, REAL runner 설계, dirty worktree 보존 검토를 읽기 전용으로 병렬 수행하고 메인이 파일 소유·통합·실제 검증을 담당한다.
- 검증: 시작 전 vectorbt REAL 게이트 관련 70개 회귀가 통과했다. W1은 운영 DB를 `REPEATABLE READ READ ONLY`로 조회해 v3 SHA·11 member·행 수·schema·issue scope를 대조했고, 병렬 설계 검토의 핵심 회귀 140개가 통과했다.
- 범위 변경: 최초 3~5시간 추정을 정정했다. 안전한 첫 REAL smoke는 Gate A/B·정산·원장·수명주기 구현까지 2~4 작업일로 재산정했다. v3의 generic 가격 issue 301건은 식별 키가 없으므로 raw/adjusted completeness 기반 보수적 과잉 제외를 적용하되 limitation으로 남긴다.
- 승인: 사용자가 로컬 구현·검증·실행을 요청했다. 커밋·푸시·운영 DB 쓰기는 요청 범위에 포함하지 않는다.
