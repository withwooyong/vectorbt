# 재납품 명세: 원문 대조와 역사 입력을 분리해 인수한다

이 명세는 수집 담당이 가격 오류를 재현하고 2015~2023 백테스트 입력의 빈 영역을 보완하기 위한 산출물 계약이다. **먼저 고정 34개 표본의 원문·변환·실행 계보를 대조하고, 역사 자료는 기간과 종목 정체성을 증명할 수 있는 형태로 납품한다.** 조사만으로 원본 수정이나 수집을 승인한 것은 아니며, 이 문서를 외부에 전송하지 않았다. 전체 데이터 인수는 현재 `BLOCKED`다.

원문 표본은 [기계 판독 요청서](sample-request.json), 현재 확인한 가격 경로는 [가격 조사](price-provenance.md), 역사 자료별 확보 경로·접근 한계는 [출처 조사](historical-sources.md)를 따른다. 아래 필드는 논리적 계약이며 기존 DB 테이블에 즉시 추가하라는 변경 지시가 아니다. 기존 [백필 계약](../../backfill-contract.md)의 P0/P1 구분을 유지한다. 더 최근 [사용자 결정](../user-decisions-2026-09-13.json)에 따라 미검증 자료의 탐색용 수익률도 실행하지 않는다.

## 1. 첫 납품은 34개 표본의 원문과 변환 재현이다

요청서에는 **KRX 라벨 표본 9개와 KIWOOM `102950` 표본 25개**의 종목 ID·코드·거래일·DB 값·수집 시각·행 해시가 들어 있다. KRX는 세 비정상 유형별 `(stock_id, trading_date)` 순 첫 3개, KIWOOM은 종가 0↔양수 전환 및 최초 봉 전후 달력 3일 이내를 선택했다. 전수 오류의 통계적 대표 표본이 아니라 원인 대조용 고정 표본이다.

| 묶음 | 확보할 자료 | 성공 조건 |
| --- | --- | --- |
| A — KIWOOM 경계 | `102950` 요청 키의 원 ka10081 응답, 수정/비수정 요청 모드, 가격·거래량·거래대금 단위, 조정 정의 | 문자열→파서→저장 결과와 DB 0/1 경계를 재현하거나 정확한 차이를 기록 |
| B — 수정주가 upstream | KRX 라벨 표본을 만든 실제 시세 공급원 응답, 요청 인자와 수집 라이브러리 버전, 변환 전 DataFrame 값·dtype | 확인된 실제 upstream과 표본 값을 연결. DB 라벨만으로 원천을 추정하지 않음 |
| C — 실행 계보 | 실행 ID·시각·코드 commit·이미지 digest·의존성 버전·실행 인자·페이지/응답 파일 hash | 현재 배포 버전과 과거 수집 당시 버전을 구분하고 표본별 실행에 연결 |
| D — 상태·행사 | 표본일의 정지/비거래·기업행사·코드 승계 원문 및 유효기간 | OHL 0을 정상 비거래로 분류하려면 날짜가 있는 원천 근거로 설명 |

당시 원문이 없으면 `historical_capture=unavailable`과 확인한 보관 경로·사유를 납품한다. 새 조회는 `new_observation`으로 분리하고 취득 시각·응답 hash·소급수정 가능성을 남긴다. **새 응답이 DB와 같아도 과거 수집 원문이 복구된 것은 아니다.** 인증 토큰·키는 요청서나 원문 부속물에 포함하지 않는다.

가격 계보에는 `stored_vendor_label`, `collector_library/version`, `upstream_provider/endpoint`, `request_adjustment_mode`, `price_basis_definition`, `captured_at`을 각각 기록한다. 공급자 라벨을 단순 덮어쓰는 대신 원 라벨과 확인 근거를 보존한다.

## 2. 역사 자료는 효력일과 당시 알 수 있었던 시점을 함께 납품한다

아래 여섯 묶음은 전체 인수에 필요한 최소 입력이다. 공식 출처의 실제 제공 기간을 먼저 확인하고, 해당 기간을 제공하지 않으면 `unavailable` 범위로 남긴다. 현재 종목 마스터나 공시 제목만으로 없는 이력을 채우지 않는다.

| 묶음 / 등급 | 최소 필드 | 검증 조건 |
| --- | --- | --- |
| 가격·조정 / P0 | 영구 종목 ID, 거래일, raw/adjusted OHLC, 거래량·대금, 단위, 가격/수량 계수, 반올림, 조정 기준일 | 원가격→조정가격 재현. 서로 다른 조정 기준·원천을 구분하고 행사와 연결 |
| 기업행사 / P1 | event_id, 유형, 영구 종목 ID, 공시 ID, 발표·접수 시점, 효력일, 기준일·지급일(해당 시), 수량비율·주당현금(해당 시), 정정/취소 연결, 원문 hash | 종류별 필수 필드를 적용. 접수일·기준일·권리락일을 혼용하지 않음. 제목 분류만으로 인수 금지 |
| 종목·코드 이력 / P1 | 영구 ID, 종목코드·ISIN 등 원천 식별자, 유효 시작/종료, 당시 시장·상품유형·업종, 상장/이전상장/승계 근거 | 유효기간 중복·단절 설명, 현재코드의 과거 재사용을 분리. 당시 보통주 필터 복원 |
| 거래 상태·상폐 / P1 | 종목 ID, 사건 ID, 정지/재개 시작·종료, 사유, 공식 상폐일, 마지막 거래일, 청산·합병·현금정산 근거 | 마지막 관측일과 공식 상폐일 분리. 무거래·정지·결측을 구분하고 상폐 보유분 처리 근거 확보 |
| 공식 거래일 / P1 | 시장, 현지 날짜, 개장 여부, 개장/폐장 시각, 임시휴장·단축장 사유, 근거 문서·발표 시점 | 종목별 기대 행 계산을 위한 외부 달력. 관측 가격 날짜의 합집합으로 대체 금지 |
| 실행·정정 / P0 | dataset_id/revision, 추출 범위·시각, 코드/이미지/요청 인자, 파일 행 수·스키마·SHA-256, 이전 revision·변경 키 수/사유 | 파일 동일성·재실행 가능성 검증. 기존 스냅샷/실험 보존 |

모든 이력 행에는 `source_id`, `source_url_or_document_id`, `published_at` 또는 그 정밀도·미확정 사유, `effective_from/to`, `captured_at`, `raw_file_sha256`를 연결한다. 현재 확보한 시각을 과거 인지 가능 시각으로 소급하지 않는다. 날짜만 제공되는 경우 장중 시점을 임의로 생성하지 말고 시간 정밀도와 후속 적용 정책을 별도 명시한다.

분석 범위는 2015-01-02~2023-12-31이다. 직전부터 이어진 상장·정지 상태와 지표 준비 기간의 자료가 필요하면 경계 이전의 선행 근거를 별도 표기한다. 2024년 이후 가격 및 성과는 이 납품 범위에 포함하지 않는다. 비용·호가 자료는 기존 계약의 별도 미완료 영역으로 유지하며 이번 역사 출처 조사로 검증 완료 처리하지 않는다.

## 3. 납품 후 검증은 세 단계로 진행한다

1. **파일·계보 검사:** 필수 필드, 행 수·hash·원문 연결, 기간과 코드 매핑, 이전 납품과의 변경 키를 확인한다. `unavailable`은 빠진 값의 은폐를 막는 기록이며 인수 통과가 아니다.
2. **가격·역사 정합성:** 34개 표본 재현 → 같은 원인으로 분류할 전체 영향 키 열거 → 공식 거래일·상태를 결합한 유효 가격 규칙과 기대 종목일 검사를 수행한다. 허용 오차를 넓혀 원인 미확정을 숨기지 않는다.
3. **새 스냅샷 인수:** 근거 있는 정정·상태 분류를 새 revision에 담아 기존 읽기 전용 검증을 반복한다. 데이터 인수와 실제 정수주·기업행사·비용 어댑터 검증이 모두 끝난 뒤에 실제 백테스트를 검토한다.

이 명세의 완료 기준은 **필요 자료·대조 키·필드·검사 기준이 구체화되어 담당자가 이행할 수 있는 상태**다. 과거 원문 복구, 원본 정정, 수집 실행과 실제 데이터 인수는 다음 단계다.
