# OHLCV20 계수 v2 전달 인수표와 미승인 키 영향 분석

> 보존 시점 안내(2026-09-23): 아래 정책·생성기 해시 일치와 신호 승인 상태는 최초 분석 당시 기록이다. 이후 공급자 변경과 006740 직접 증거의 미연결 상태는 [후속 인계](../006740-evidence-handoff-2026-09-23.md)를 따른다. 이번 통합 보존 요청으로 커밋·푸시 범위가 추가됐다.

이 작업의 목적은 **백테스트를 막는 자료 문제를 종목·날짜별로 좁히고, ted-startup의 자료 보완과 vectorbt의 입력 검증·연결 책임을 나누는 것**이다. 현재 정책과 생성 코드의 해시가 일치하는 계수 v2의 733키를 전수 대조했다. 가격 643키·거래량 539키가 부분 승인되어 있고, 배정비율 때문에 거래량이 막힌 104키는 84종목에 걸친다. 이 중 50키가 자격을 충족한 후보의 60거래일 신호 준비창과 겹치며 중복 제거 후 2,383종목·일이다. **이는 자료 의존 범위이지 실제 신호·주문·거래·보유 건수가 아니다.**

범위는 기존 로컬 원문과 2014년 준비자료, 2015-06-15~2023년 평가구간이다. 백테스트·신호 생성·운영 DB 접근·원자료 및 정책 정정·커밋·푸시는 하지 않았다. 실제 신호·주문·보유·수익률은 `null`로 남겼다. 원문 감사와 최종 독립 검토 상태는 [작업 WBS](wbs.md)를 따른다.

먼저 §1에서 인수 기준과 저장소별 책임을 확인하고, §2~3에서 미승인 키가 어떤 자료 의존성을 만드는지 읽는다. 배정비율 원문 감사는 §4, 재현 방법·한계·다음 작업은 뒤에 둔다. 733키 전체는 [JSON 인수표](impact-v2/intake-733.json)와 [Parquet 인수표](impact-v2/intake-733.parquet), 입력 필드별 계약은 [소비자 계약](consumer-contract.md)에 있다.

## 1. 현재 인수 기준은 계수 v2이며 부분 승인은 실행 승인이 아니다

이번 시작 HEAD는 vectorbt `ceae86d46265095d898aaf9709087e41a2d4dc85`, ted-startup `c30e371eaed4fc10f8a30175581e8c1b181438c7`이다. 이전 준비도 점검 이후 vectorbt에 v2 계수 입력 연결 커밋이 추가됐다. 따라서 과거의 “v1 파일 고정 소비·모든 조정값 false” 설명을 이번 현재 상태에 적용하지 않는다.

계수 v2의 정책·후보 보고서·생성기 2개·후보 파일·감사 Parquet·corrected-v4 manifest 해시를 대조했다. 수정된 v4 봉인 파일 106개, 공식 달력과 일별 자격 원천도 검증하고 분석 종료 시 입력 해시를 다시 확인했다. v3라는 번호의 미추적 잔여 증거는 현재 정책·생성기 해시와 맞지 않아 사용하지 않았다.

아래는 데이터 전달과 실행 의존성을 구분한 인수 요약이다. 계수 승인 건수는 사건 키 수이며 신호 수나 종목 수가 아니다.

| 전달 항목 | 이번 확인 | 남은 조건·책임 |
| --- | --- | --- |
| corrected-v4 원가격·월 후보·오버레이 | 봉인 manifest 및 파일 해시, 달력·일별 자격 대조 | ted-startup이 원천·정정·완전성 증명, vectorbt가 불변 입력 인수 |
| 계수 v2 733키 | 양쪽 승인 539 / 가격만 승인 104 / 양쪽 미승인 90 | ted-startup이 키별 배정비율·행사 종류·공시 시점·정정 이력 보완 |
| 현재 조정 입력 어댑터 | v2 audit hash를 받아 가격·거래량 유효성을 각각 계산 | vectorbt가 공급자 조정종가 비교, 시점별 신호 입력 계약을 검증 |
| 신호용 계수·행사 커버리지 | `signal_admitted=false`; 계수 건수로 승격하지 않음 | 관련 행사 누락과 `known_at`/장 마감 전 공개 증거를 확인 |
| 권리·상장·매도·공식 하한가 | 19사건·31권리 계약과 REAL 코어의 요구는 별도 | ted-startup 사실 전달 + vectorbt 장부·승인 영수증 결속 검증 |
| REAL 실행 | `real_execution_admitted=false` 유지 | 모든 선행 입력과 검증을 통과하기 전 실행하지 않음 |

## 2. 배정비율 104키의 우선순위를 신호 준비 의존성으로 좁혔다

104키는 가격 계수는 승인되었지만 거래량 계수가 미승인인 키와 정확히 일치한다. 산식 불일치 50키와 파싱 실패 54키는 서로 겹치지 않는다. 아래의 ‘키·일’은 같은 종목·날짜에 여러 사건이 관련되면 중복되며, 실제 거래량이나 거래 횟수가 아니다.

| 현재 차단 사유 | 키 수 | 신호 준비 의존 있는 키 | 의존 키·일 합계 | 사건 이전 주문 자격이 관측된 키 |
| --- | ---: | ---: | ---: | ---: |
| 배정비율 대조 불일치 | 50 | 19 | 884 | 34 |
| 배정비율 미해석 | 54 | 31 | 1,535 | 45 |
| 합계 | 104 | 50 | 2,419 | 79 |

- 104키의 신호 준비 의존은 **2,383 고유 종목·일**이다. 이들 날짜에서 다음 공식 거래일의 주문 자격도 확인되는 것은 **2,367 고유 종목·일**이다. 매수 임계값, 후보 순위, 슬롯 여유, 가격 체결, 주문·보유 장부는 계산하지 않았다.
- 신호 준비 의존이 없는 54키 중 **34키는 사건 이전 주문 자격이 관측**됐다. 현재 후보 창에서 보이지 않는다는 이유만으로 보유·권리 영향을 배제할 수 없다.
- 나머지 20키는 이번 관측 범위에서 두 종류의 자격 노출이 모두 없었다. 이는 영향 0이나 사건·종목 제외 승인으로 해석하지 않는다. 준비구간·과거 권리·자료 완전성 등 다른 의존성은 별도다.

## 3. 전체 미승인 194키와 현재 어댑터 차단 범위는 다른 집계다

미승인 사건은 총 194키(104+90)이며 가격 미승인 90키가 여기에 포함된다. 다른 미승인 90키 중 45키에서 2,296고유 종목·일의 신호 준비 의존을 확인했다. 104키와의 중복을 제거한 전체 합집합은 **4,670종목·일**이다. 부분 집계 2,383+2,296을 그대로 더하면 중복을 포함하게 된다.

현재 어댑터의 과거 봉 검증은 각 봉 **이후 2023년까지 발생한 모든 사건**의 승인 여부를 사용한다. 반면 신호 코드는 신호일 직전 60거래일 창 안의 사건과 그때 알려진 사실을 사용한다. 아래 값은 두 방식을 같은 뜻으로 취급하지 않기 위해 나눠 기록했다.

| 집계 | 범위 | 관측값 | 의미 |
| --- | --- | ---: | --- |
| 미승인 사건의 신호 준비 의존 | 2015-06-15~2023년, 자격 충족 후보 | 4,670종목·일 | 인과적 60세션 입력 의존, 실제 신호 아님 |
| 가격 미승인 이후 사건이 있는 과거 봉 | 같은 평가구간 | 34,790행 | 어댑터의 가격 계수 검사 의존 |
| 거래량 미승인 이후 사건이 있는 과거 봉 | 같은 평가구간 | 112,018행 | 어댑터의 거래량 계수 검사 의존; 위 가격 행 포함 |
| 어댑터 조정가격 유효 봉 | 2014~2023 전체 입력 | 1,436,344행 | 가격 계수와 공급자 조정종가 대조 통과 |
| 어댑터 공급자 조정종가 불일치 | 2014~2023 전체 입력 | 189,862행 | 가격 사건 승인 조건 충족 후에도 값 대조 불일치 |
| 어댑터 공급자 조정종가 비교 불가 | 2014~2023 전체 입력 | 159,779행 | 가격 사건 승인 조건 충족 후 비교할 값 부족 |

가격과 거래량의 유효성은 별도 플래그다. 거래량이 미승인이라고 가격 유효성까지 자동으로 false가 되는 것은 아니다. 배정비율 104키를 해결해도 다른 미승인 90키, 공급자 가격 대조, 완전한 사건 커버리지와 권리·실행 검증이 남는다. **나중에 알려진 행사·품질 문제를 근거로 과거 종목이나 신호를 사후 제외하지 않는다.**

## 4. 배정비율 원문 감사

104키 전체의 기존 근거와 저장 원문 가용성을 분류했다. [원문 감사 보고서](allotment-104-review.md)에 104행 판정표가 있고, [상세 JSON](allotment-104-audit.json)에 공시번호·파일·해시·원문 필드·비율·오차·미확정 사항이 있다. 저장 원공시 전체가 있는 키는 53개, 일부 후보 원문만 있는 키는 2개, 해당 키 원문이 저장되지 않은 것은 49개다. 53은 목표 사건의 유효 매칭이나 권리 확정 건수가 아니며, 기준일이 맞지 않는 2키도 포함한다.

아래 분류는 서로 겹치지 않아 합계가 104다. ‘신호 준비 의존 키’는 §2의 60거래일 의존과 일별 자격이 관측된 키이며 우선 조사 순서를 위한 근거다.

| 원인 | 키 수 | 신호 준비 의존 키 | 다음 확인 |
| --- | ---: | ---: | --- |
| 주주 배정비율과 총발행주식 기준 실효비율의 차이 | 45 | 18 | 자기주식·단수주·분모 범위와 가격/거래량 계수의 의미 대조 |
| 원문 표 모순 + 콤마 숫자 파싱 | 1 | 0 | 208340의 원문 표와 본문을 함께 검증; 파서 앞 숫자 절단 수정 검토 |
| 직접·실효비율 모두 가격 역산값과 불일치 | 4 | 1 | 기준가격·anchor·동시 행사 대조 |
| 저장 검색 결과에 정책 제목 후보 없음 | 42 | 24 | 검색 기간·기업코드·제목·원문 연결 감사; 공시 부재로 단정 금지 |
| 정책 제목 후보 복수 | 9 | 5 | 복수 후보의 발행 주체·기준일·사건 일치 대조 |
| 유일 후보의 기준일 불일치 | 2 | 1 | 목표 사건에 해당하는 공시 재연결 |
| 보통주 비율 없음·종류주식만 있음 | 1 | 1 | 종류주식 수치를 보통주에 적용하지 않고 차단 유지 |

불일치 50키 가운데 **45개 일반 사례와 208340 특이 1개, 총 46키**는 `1 + 신주 수 / 행사 전 총발행주식 수`라는 실효계수를 쓰면 가격 역산값과 0.5% 이내로 맞는다. 그러나 현행 정책의 `1 + 주주별 배정비율`과 다른 산식이므로 이것만으로 승인할 수 없다. 자기주식 제외·단수주 처리와 정합적인 관측이며 모든 사건의 원인을 확정한 것은 아니다. 060720은 일반 45키에 이미 포함되고 208340도 46에 포함되므로 다시 더하지 않는다.

`208340/2020-06-30`은 표의 1주당 배정 칸에 `6,910,809`가 있고 본문은 1주당 1주라고 설명한다. 기존 파서는 콤마 앞 `6`을 읽었다. 원문 자체 모순과 파싱 문제를 함께 보존했으며, 본문 1을 임의로 승인값에 넣지 않았다. 남은 4키는 `089030/2022-08-01`, `097780/2017-05-30`, `131970/2020-09-15`, `137400/2019-05-07`이다.

**104키 모두 현행 거래량 미승인을 유지한다.** 원문 미저장은 공시 부재나 수집 누락 확정이 아니며, 검색 후보가 있어도 목표 종목·사건의 공시임을 추가로 증명해야 한다.

## 5. 방법론과 재현

키는 `(stock_code, effective_date)`다. 신호 준비 의존은 공식 거래일 `t`에 대해 `calendar[t-60] < effective_date <= calendar[t]`인 날짜를 구하고, 원가격 행 존재·월 후보·일별 시총/분류/거래 가능성 자격과 교집합을 취했다. 이는 현재 `ohlcv20_signal.py`의 사건 선택 구간이다. 61봉 연속 존재는 신호일을 포함한 원가격 행의 존재만 검사하며, 모든 행의 `can_signal`이나 행사 커버리지 승인을 대신하지 않는다.

다음 거래일 주문 자격은 전일 사실로 판정된 기존 eligibility를 사용했다. 실제 신호·순위·매수 한도·슬롯·주문·체결은 계산하지 않았다. 보유 영향은 사건 이전 주문 자격이 있는 날의 전체 수 및 이전 1·3달 수를 별도로 보존했다. 정지·부분매도 때문에 실제 보유는 3개월을 넘을 수 있고, 사건 유효일은 권리 기준일과 다를 수 있다. 실제 보유·권리 귀속 판정은 `null`이다.

기존 원문·Parquet만 읽는 감사 스크립트를 재사용할 수 있다. 이미 존재하는 출력 디렉터리는 거절한다. 새로운 출력 이름을 사용하고 기존 증거를 덮어쓰지 않는다.

```powershell
.venv\Scripts\python.exe -B scripts/research/audit_ohlcv20_factor_intake.py `
  --ted-root C:\Users\aeby\vscode\ted-startup `
  --out docs/strategy-research/backtest-lab/ohlcv20-factor-v2-intake-2026-09-23/impact-new

.venv\Scripts\python.exe -B -m pytest tests/research/test_ohlcv20_factor_intake_audit.py -q -p no:cacheprovider
```

`impact-v1`은 최초 결과다. 독립 검토에서 eligibility 영수증의 manifest·기간 결속을 강화한 뒤 `impact-v2`를 다시 만들었다. 두 실행의 733키 인수표와 의존성 파일 해시는 같고 수치도 같다. 최신 기준은 [impact-v2/summary.json](impact-v2/summary.json)이며 입력 전체 경로·해시와 출력 해시가 있다. 원자료가 달라지거나 실행 중 입력이 바뀌면 오류로 종료한다.

## 6. 검증 및 다음 단계

영향 분석 단위 테스트 9개가 통과했다. 60세션 엄격 경계·휴장일 사건·준비기간·미래 사건·지연 청산 해석·기존 출력 보존·manifest/기간 변조 거부를 확인했다. 핵심 오류 Ruff 검사도 통과했다. 독립 검토는 733 유일키·JSON/Parquet 동등성·출력 해시·집계 중복·실제 건수 null을 재대조했다. 전체 제품 테스트나 백테스트는 실행하지 않았다.

**추천 다음 작업은 ted-startup에서 ‘배정비율 분모와 거래량 조정 단위의 의미 검증’이다.** 일반 45키 중 신호 준비 의존이 있는 18키를 먼저 보고, 주주 배정대상 수·자기주식·신주 총수·단수주 처리와 KRX 공식 기준가격 산식을 대조한다. 실효계수 46키가 맞는다는 관측만으로 현재 정책을 바꾸지 않는다. 완료 기준은 직접 배정비율과 실효 총주식 비율이 각각 어떤 가격·거래량 단위를 표현하는지 공식 근거로 설명하고, 현행 정책 유지로 해소 가능한 자료 오류와 별도 정책 판단이 필요한 사례를 구분하는 것이다.

동시에 확보 가능한 미해석 54키의 원문 연결·파서 보완은 별도 데이터 과제로 남긴다. 데이터 정정·계수 재승인은 ted-startup에서 새 증거로 수행하고, vectorbt는 새 전달물 인수·시점별 신호 입력 연결과 장부 검증을 담당한다. 이번 분석 완료가 그 후속 작업이나 백테스트 실행의 승인은 아니다.
