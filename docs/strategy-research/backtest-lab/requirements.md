# Backtest Lab 요구사항

## 목적과 적용 범위

이 문서는 Backtest Lab의 구현 인수 기준을 정한다. 기술 분석 전략의 일괄 백테스트·결과 저장·비교·조건부 선정만 다루며, AI 뉴스·증권사 실시간·모의·실전 주문은 제외한다. 상세 전략 수식과 실험 조합 수, 사전 정렬 기준, CLI 형태는 [전략 명세](strategy-spec.md)와 [기술 명세](technical-spec.md)에 위임한다.

모든 `FR`은 구현 전 설계 계약이며 이번 문서 작성이 프로그램 구현이나 전략 선정을 뜻하지 않는다. `AC`는 각 요구사항이 충족되었다고 판단할 수 있는 최소 관찰 증거다.

## 기능 요구사항

| ID | 요구사항 | AC |
| --- | --- | --- |
| FR-001 | 실행은 raw/adjusted·달력·유니버스·기업행사·비용 데이터 manifest와 관측 기준일을 입력으로 고정한다. | 결과마다 시작·종료일, 행·종목 수, 데이터 버전·해시, 조정가격 계보 상태가 저장된다. |
| FR-002 | 종가 0, OHLC 비양수, 결측, 거래정지·상장폐지 의심 레코드는 사전 규칙으로 분류한다. | 제외·보류·예외별 건수와 종목·일자 표본, 정책 버전이 결과에 남는다. 원인 미확정 레코드를 정상 체결로 만들지 않는다. |
| FR-003 | 역사적 유니버스와 가격 계보가 미확정이면 실행 결과에 한계를 표시한다. | 보고서와 리더보드에 `data_limitation` 상태와 해당 범위가 표시된다. |
| FR-004 | 시스템은 전략 명세가 허용한 여러 기술 전략·파라미터·매도 모델을 하나의 실험 묶음으로 실행한다. | 묶음 ID 아래 모든 계획 실행이 SUCCEEDED/FAILED/BLOCKED/CANCELLED/INTERRUPTED 중 하나로 설명되며 RUNNING의 무기한 방치를 탐지한다. 재사용은 원본 run 참조를 보존한다. |
| FR-005 | 각 전략은 완료 거래일 데이터만으로 신호를 만들고 다음 거래일 이후의 가격으로만 체결을 시도한다. | 신호일·주문일·체결시도일이 거래 장부에 분리 저장되고 미래 시점 입력 검사가 통과한다. |
| FR-006 | 매수 계획은 진입 전에 이익실현가와 손절가를 모두 기록한다. | 거래마다 전일 종가·ATR 등 입력값, TP·SL 가격, 규칙 버전, 계획 시각이 있다. |
| FR-007 | 진입은 다음 거래일 시가의 사전 정의한 매수 가능 가격 범위에서만 시도한다. | 범위 밖 갭, 결측, 거래정지, 현금 부족은 미체결 또는 거절로 남으며 임의 체결가가 생성되지 않는다. |
| FR-008 | 실제 체결가가 계획가와 달라도 TP·SL을 체결 뒤 임의로 재산정하지 않는다. | 계획된 TP·SL과 체결된 진입가가 함께 보존되고 후행 변경은 새 전략 버전 없이는 불가하다. |
| FR-009 | 가격 기반 TP·SL·시간 청산은 가장 먼저 발생한 청산 후보를 처리한다. | 각 거래에 청산 사유, 후보 시각, 체결·미체결·재시도 상태가 하나 이상 기록된다. |
| FR-010 | 최대 보유 기간은 `entry_date + calendar 1 month` 말일 clamp로 계산한다. | 월 말 날짜가 존재하지 않는 진입일의 계산 사례가 포함되고, 비거래일이면 직전 거래일 시가 청산 시도가 기록된다. |
| FR-011 | 거래정지 등으로 시간 청산이 불가능하면 강제 체결하지 않는다. | 포지션은 `overdue_unfilled`로 남고 초과 보유 일수, 재시도, 마지막 검증 가격이 기록된다. |
| FR-012 | 일봉 한 봉에서 TP와 SL이 함께 닿으면 기본 결과는 손절 우선으로 계산한다. | 동일 입력에서 손절 우선 결과와 갭·충돌 민감도 결과가 구분되어 저장된다. |
| FR-013 | 포트폴리오는 초기 원금 1억 원, 인출 0, 이익 재투자를 기본 연구 조건으로 지원한다. | 실행 설정과 일별 현금·평가액·실현/미실현 손익이 보존된다. |
| FR-014 | 외부 비상자금 1~2억 원은 자동 편입·이체·인출 대상이 아니다. | 백테스트 자금 흐름에 외부 계정 식별자나 자동 자금 이동이 없고, 설정 검사가 이를 거절한다. |
| FR-015 | 기본 최대 보유 종목 수는 20이며 미체결 진입 계획도 점유 규칙에 포함한다. | 한 거래일에도 보유·예약·미체결 종목 합집합의 고유 종목 수가 20을 넘지 않으며 초과 후보의 처리 사유가 남는다. |
| FR-016 | 자산 성장 정책은 종목 수 확대와 종목당 금액 확대를 별도 포트폴리오 정책으로 비교한다. | 두 정책은 같은 전략·기간·비용에서 별도 실행 ID와 비교표를 가진다. fixed20을 기술 비교 기준으로 쓰고, 최종 성장 정책은 사전 기준으로 비교 후 고정한다. |
| FR-017 | 실험 묶음은 중단 뒤 완료된 하위 실행을 재사용하고 미완료 실행만 재개할 수 있다. | 재개 전후 실행 ID·입력 해시가 대사되고, 중복 결과·누락 결과 없이 최종 상태가 확정된다. |
| FR-018 | 모든 실행은 거래·주문시도·미체결·예외·일별 포트폴리오·요약 성과를 저장한다. | 성공 실행뿐 아니라 실패·스킵·중단 이유를 조회할 수 있다. |
| FR-019 | 비교 화면 또는 보고서는 수익률, MDD, 거래 수, 비용, 현금 비중, 미체결·예외와 데이터 제외를 함께 제공한다. | 동일 실험 묶음의 후보를 같은 기간과 정의로 비교한 표가 생성된다. |
| FR-020 | 리더보드는 정렬 결과와 선정 결과를 구분한다. | 리더보드 1위가 선정되지 않은 경우와 `NO_SELECTION` 사례를 표현할 수 있다. |
| FR-021 | 조건부 최고 후보는 사전 고정한 데이터·실행 가능성·기간 분리·위험 게이트를 모두 통과한 하나만 선정한다. | 게이트 입력, 판정 결과, 탈락 사유, 동률 처리와 선택 근거가 저장된다. 통과 후보가 없으면 `NO_SELECTION`을 반환한다. |
| FR-022 | 기간 분리는 개발·검증·잠금 구간을 명시하고, 잠금 구간을 본 뒤 변경한 규칙을 재분류한다. | 실행마다 구간 정의와 규칙 버전이 저장되며 잠금 구간 사용 이력이 보고된다. |
| FR-023 | HTS 이식 태그는 각 기술 조건에 `mapped`, `partial`, `unmapped`, `unknown`을 표시한다. | 태그 근거와 미확정 차이가 결과에 남으며, 태그만으로 HTS 결과 동일성이나 실시간 주문 지원을 주장하지 않는다. |

## 비기능 요구사항

| ID | 요구사항 | AC |
| --- | --- | --- |
| NFR-001 | 재현성: 같은 입력 manifest·전략·설정·엔진 버전은 같은 실행 식별자와 비교 가능한 결과를 낸다. | 재실행 대사에서 입력 해시·거래 수·핵심 성과 차이가 설명되거나 오류로 표시된다. |
| NFR-002 | 관측성: 실행 단계, 진행량, 제외, 예외, 자원 사용, 재개 상태를 기록한다. | 실패한 하위 실행의 마지막 단계·오류·재개 가능 여부를 원본 로그 없이 조회할 수 있다. |
| NFR-003 | 자원 제어: 대규모 조합 실행은 동시성·메모리·저장량을 설정으로 제한한다. | 한도 도달 시 새 실행은 안전하게 대기·스킵·중단하고 이미 저장한 결과를 손상하지 않는다. |
| NFR-004 | 보안과 읽기 전용: 데이터 원본과 외부 계좌·브로커에 쓰기 작업을 하지 않는다. | 구현 권한·연결 설정 검토에서 데이터 원본 변경, 주문, 자금 이체 호출이 없다. |
| NFR-005 | 감사 가능성: 결과가 어떤 데이터·규칙·코드·환경에서 나왔는지 추적한다. | 단일 거래와 단일 리더보드 행에서 실행 ID, manifest, 전략 버전, 설정 버전을 역추적할 수 있다. |
| NFR-006 | 실패 격리: 한 전략·종목·기간의 오류가 실험 묶음 전체 결과를 삭제하거나 성공 결과를 덮어쓰지 않는다. | 의도적 오류 주입 뒤 실패 행은 저장되고 독립 실행은 계속 또는 명시적 중단 정책에 따라 종료된다. |

## 인수 범위와 미결 사항

인수는 이 문서의 AC와 [기술 명세](technical-spec.md)의 저장·실행 계약을 함께 충족해야 한다. 전략 식, 비용 모델, 갭 민감도, 실험 규모, 사전 정렬 기준와 선택 게이트의 구체 수치는 [기술 명세](technical-spec.md)에 제안되어 있으며 성과 열람 전에 고정한다.

허용 MDD는 미정이다. 10%·20%·30% MDD 스트레스는 연구 비교 제안이며 실전 승인 기준이 아니다. adjusted-only 데이터, 가격 계보, 역사적 유니버스, 종가 0과 OHLC 비양수 원인이 해결되기 전에는 어떤 리더보드도 실전 적합 판정이나 최고 전략의 확정 근거가 될 수 없다.
