# 기술 명세: 일괄 실행·전체 결과 저장·단일 전략 선정

이 명세는 **한 설정으로 48개 기술전략을 공동 계좌에서 실행하고, 실패까지 저장한 뒤 조건에 맞는 한 전략을 고르는 연구 프로그램**의 구현 계약이다. 1억 원·외부 입출금 0·익절/손절 사전 지정·달력 최대 1개월은 [전략 명세](strategy-spec.md)를 따른다. 아래 내용은 전체 목표 명세다. **연구 핵심 구현을 추가했지만 정식 데이터 인수·현실 비용·기업행사·후속 잠금 단계는 미완료**이며, 현재 실행 가능한 범위는 [구현·실행 결과](implementation-and-results-2026-09-13.md)에서 구분한다. [설정 예시](experiment-config.example.json)는 설계용 기계 판독 예시이며 실행용 설정은 새 CLI의 `config` 명령으로 생성한다.

핵심 선택은 vectorbt의 지표·수치 계산·포트폴리오 기능을 재사용하면서, 공동 현금·동봉 청산·기간 제한을 명시적인 이벤트 순서로 구현하는 것이다. API의 기본 옵션만 켜서 시장 모형이 완성됐다고 보지 않는다. 이 문서는 구조→데이터/계좌→배치/선정→저장/복구→검증 순서로 읽는다.

## 1. 모듈과 책임 경계

새 연구 코드는 저장소 루트 `research/krx_lab/` 아래 별도 Python 패키지로 추가하는 안이다. vectorbt 제품 API와 기존 단일종목 예제는 변경하지 않는다. 현재 패키지는 생성됐으며 아래 모듈 책임 중 일부는 합쳐 구현했다. 정확한 구현 범위는 실행 결과 문서를 따른다.

| 모듈 | 책임 | 주요 입력 → 출력 |
| --- | --- | --- |
| `config.py` | 설정 검증·정규화·버전 고정 | JSON/YAML → canonical config와 해시 |
| `snapshot.py` | PostgreSQL 읽기 전용 추출·출처 고정 | 범위·영구 종목 ID → Parquet/manifest |
| `quality.py` | 가격 의미·달력·상태·유니버스 게이트 | 스냅샷 → 검사/격리 사유·사용 등급 |
| `indicators.py`, `strategies.py` | 공유 지표 캐시·12개 진입 계산 | 시점 고정 입력 → signal events |
| `execution.py`, `portfolio.py` | 계획 가격·정수주·현금·청산 | 신호·사전 정책 → 주문·체결·현금/포지션 |
| `runner.py`, `registry.py` | 배치 계획·상태·재시도·재개 | 후보×구간×시나리오 → run registry |
| `metrics.py`, `selection.py` | 비용 후 지표·게이트·고정 순위 | 실행 결과 → leaderboard·선정 manifest |
| `report.py`, `cli.py` | 상태 조회·사람이 읽는 비교 보고서 | registry·metrics → HTML/Markdown/CSV/JSON |

초기 엔진은 `numba`로 고정하고 실행 시 버전을 기록한다. Rust 비교는 별도 성능 작업이며 본 결과의 의미를 바꾸지 않는다. `Portfolio.from_order_func(..., flexible=True)` 또는 일자 내 단계 이벤트로 변환한 `from_orders` 어댑터를 작은 회귀 사례로 선택한다. 후자를 사용하면 **수량·현금·순서를 결정하는 인과적 시뮬레이터가 먼저 있어야** 하며 사후 신호로 주문을 만드는 형태를 금지한다.

공식 API는 신호·주문·사용자 정의 주문 함수 경로를 구분하고 공동 자금을 그룹별로 다룬다. 로컬 `vectorbt/portfolio/base.py`를 기준으로 같은 종목 당일 진입·청산과 공동 현금 사례를 검사한 뒤 구현 방식을 고정한다. [vectorbt Portfolio API](https://vectorbt.dev/api/portfolio/base/)

## 2. 데이터 등급과 일자 축

| 등급 | 허용 실행 | 최종 선정 |
| --- | --- | --- |
| `SYNTHETIC` | 엔진·상태·장부 테스트 | 불가 |
| `EXPLORATORY_ADJUSTED` | 조정 의미를 확인한 제한 연구, 분수 단위 또는 일관된 조정 수량 기준 | 실제 1억 원 정수주 운용 후보 확정 불가 |
| `EXECUTION_ELIGIBLE` | 원가격·기업행사·달력·역사 유니버스·비용·거래 상태를 인수한 공동계좌 연구 | 나머지 검증 통과 시 조건부 선정 가능 |

가격 의미가 불명확하거나 키 무결성이 깨지면 수익률 실행은 `BLOCKED`다. 분석용 격리 행도 삭제하지 않고 사유와 거래일 축을 보존한다. 보유 중 정지·누락·상폐는 장부에서 포지션이 사라지는 방식으로 처리하지 않는다. 설명 없는 보유 평가·정산이 남으면 해당 실행은 선정 부적격이다.

스냅샷은 가격, 시점별 유니버스, 거래일, 상태, 기업행사, 날짜별 비용 파일과 각각의 SHA-256을 포함한다. 추출 SQL·스키마·소스 버전·cutoff·추출 시각을 보존한다. 장기간 repeatable-read 트랜잭션 비용을 측정해 추출 방식을 정하고 원본 DB에는 분석 테이블을 쓰지 않는다. 현재 조정 데이터만으로 raw를 역산할 수 있다고 가정하지 않는다.

지표 준비는 최초 평가일 전 **250개 공식 거래일**을 공통 기준으로 제안한다. 2015년 전 자료가 없으면 250봉 준비 뒤부터 개발 성과를 시작한다. 신규 상장 종목은 자기 이력이 지표 최소 창을 채울 때까지 제외한다. 준비 구간은 지표 계산에만 쓰고 평가 시작 전 포지션을 넘기지 않는다. EMA·RSI·ATR의 초기화 정의는 전략 명세와 독립 검산으로 고정한다.

## 3. 공동 계좌의 하루 실행 순서

모든 종목의 당일 고가·저가를 확인한 후 같은 날 시가 신규 매수에 그 현금을 쓰는 오류를 막는다. 일봉 내 순서 불확실성은 보수적 실행 규칙이지 실제 틱 재생이 아님을 결과에 표시한다.

1. **시가 전:** 기업행사·달력·거래 상태 적용, 전일까지 확정한 신호와 원화 TP/SL·진입 상한·최대 보유기한을 읽는다. 미래 종가·고가·거래량을 주문 수량에 쓰지 않는다.
2. **시가 기존 포지션:** 기한 청산과 시가 갭 손절/익절을 전략 명세의 우선순위로 처리한다. 정지·체결 불가는 거절·재시도 상태로 남긴다.
3. **시가 신규 진입:** 직전일 계좌 가치 기준 예산과 현재 사용 가능한 현금으로 후보를 고정 해시 순서로 배정한다. 동일일 청산 종목 재진입 금지, 보유·주문 예약 합집합 20개 상한, 정수주·비용 포함 예산을 검사한다.
4. **시가 이후:** 기존·신규 보유 모두 익절/손절 조건을 검사한다. 양쪽 접촉이면 기준은 손절 우선, 불확실성 플래그를 남긴다. 이 단계 매도 대금은 같은 날 시가 진입에 소급 사용하지 않는다.
5. **종가:** 미청산 평가·현금·노출·비용을 기록한다. 다음 거래일 신호·가격 계획을 생성한다. 정정된 과거 가격은 새 스냅샷으로만 반영한다.

기업행사 시 고정 TP/SL은 동일 경제적 의미가 유지되도록 확인된 가격·수량 계수로 조정하고 전후 값과 근거를 기록한다. 근거 없이 가격만 이동시키지 않는다. 부분체결 확장은 주문 예약량과 체결량을 분리하고 같은 회귀 장부를 통과해야 한다.

초기 원금은 `100_000_000 KRW`, 외부 현금흐름은 모두 0이다. 총자산은 현금+보유 평가액이며 실현수익만 더해 복리로 계산하지 않는다. 미실현 이익은 다음 날 목표 비중에 영향을 줄 수 있지만 보유 주식을 팔지 않고 그 이익을 현금처럼 쓸 수는 없다. 순손실이면 다음 주문 예산도 줄어든다.

## 4. 재투자·종목 수 비교 정책

기술 후보 선정은 먼저 `fixed20` 하나로 공정하게 비교한다. 기술전략을 고정한 뒤 같은 검증 구간에서 자금배분 정책만 비교한다. 이 두 단계를 합쳐 더 많은 자유 파라미터를 무제한 탐색하지 않는다.

| 정책 ID | 신규 주문 슬롯 | 종목당 목표 예산 | 해석 |
| --- | --- | --- | --- |
| `fixed20` | 최대 20 | 직전일 총자산×80%/20, 종목 상한 5%·위험 한도 적용 | 이익 재투자 시 개별 금액이 증가하는 기본안 |
| `staged10_15_20` | 전일 총자산 <1.5억:10, 1.5억~2억 미만:15, 2억 이상:20 | 직전일 총자산×80%/허용 슬롯, 종목 상한 5%·위험 한도 적용 | 성장 시 종목 수와 금액이 함께 바뀔 수 있는 대안 |

80%, 5%, 1.5억·2억은 **연구 제안**이다. staged 정책의 최초 10종목에서는 종목 상한 때문에 실제 최대 노출이 50%, 15개에서는 75%, 20개에서는 80%다. 결과 차이를 순수한 “종목 수 효과”라고 해석하지 않고 현금·노출과 함께 보고한다. 기존 포지션을 목표 비중에 맞춰 매일 강제 매매하지 않으며 배분은 신규 진입 시에만 적용한다.

계좌가 줄어 슬롯 기준이 낮아져도 기존 종목을 즉시 강제 매도하지 않는다. 기존 익절·손절·기한 정책을 유지하고 새 진입을 차단해 상한으로 돌아온다. 현재 설정에서 20개 초과 확대는 없다. 외부 여유자금 유입·레버리지·물타기로 성장 기준을 맞추지 않는다.

두 정책은 선정된 기술전략에 대해 2020~2023 검증 구간의 비용·위험 기준으로 비교하고 동률이면 `fixed20`을 유지한다. 성장 기준이 한 번도 도달하지 않으면 미검증 경계로 표시하고 합성 데이터로 상태 전이만 검사한다. 선정된 정책을 잠금 구간 이전에 고정한다. 선택 정책의 현실 비용 검증4년도 양수인 연도3개 이상·성장점수 양수·낙폭 한도 이내라는 기준을 통과해야 잠금을 연다.

## 5. 배치 매트릭스와 실행량

48개 후보는 [전략 명세](strategy-spec.md)의 12개 진입×4개 청산이며 후보 내부 기간·비용은 일괄 고정한다. 실패·0거래도 하나의 예정 실행으로 세며 자동으로 다른 전략을 끼워 넣지 않는다. 아래는 **계획 실행 수**이고 실제 실행 결과가 아니다.

| 단계 | 조합 | 계획 수 | 용도 |
| --- | --- | ---: | --- |
| 개발 | 48 × 2015~2019 한 구간 × 기준 30bp·지연1 | 48 | 코드/가설 검토, 준비 기간 제외 |
| 기간 분리 검증 | 48 × 2020/21/22/23 × 비용10/30/50bp | 576 | 모든 후보의 비용 차감 성과 |
| 추가 지연 검증 | 48 × 4년 × 기준30bp·지연2 | 192 | 다음 시가 대비 한 거래일 추가 지연 |
| 자금배분 비교 | 고정 기술전략1 × 정책2 × 검증4년 × 기준30bp | 8 | 종목 수·금액 확대 정책 선택 |
| 잠금 평가 | 고정 전략·정책1 × 잠금1구간 × 비용3+지연2 기준비용1 | 4 | 마지막 미사용 평가 |
| **기본 최대** | 후보와 정책이 모두 다음 단계로 진행한 경우 | **828** | 탈락·차단 시 실제 수 감소 |

`fixed20` 자금배분 4건은 이미 같은 입력의 검증 결과라면 참조 재사용한다. 따라서 828은 논리 비교 슬롯 수이고 신규 수치 계산은 최대 824건으로 줄일 수 있다. 재사용도 참조 run ID를 남긴다. 연구 탐색 과정의 설정 변경·재시도 이력은 별도로 보존한다.

비교 기준은 무투자 현금, 거래 가능한 대표 기준상품의 매수 후 보유로 제안한다. 개발1+검증4+잠금1의 6구간×2기준=12건을 별도 생성해 **840개 논리 슬롯**까지 계획한다. 잠금 해제 전에는 잠금 기준상품 성과도 숨긴다. 지수는 매매 상품과 구분하며 배당/비용 기준을 맞춘다. 기존 6개·10봉 기준선은 선택적 회귀 작업이고 840에 포함하지 않는다.

최종 후보에는 별도 필수 검사 9슬롯을 더 둔다. **현실 비용 프로필**(날짜별 수수료·매도 세금·수량·시점별 슬리피지 추정)을 선택 후보·정책에 적용해 검증4년+잠금1구간의 5슬롯을 만든다. 검증4년 결과는 잠금 전에 확인하고 부적합하면 선정 보류한다. 또한 선택 후보의 검증4년에 동봉 TP 우선·시가 목표 갭 개선 체결을 적용한 낙관 경계 4슬롯을 비교한다. 이 4개는 일봉 불확실성의 상한 설명용이고 후보 순위를 바꾸는 근거로 쓰지 않는다. 기준과 차이가 크면 분봉/체결 데이터 검증을 요구한다.

따라서 필수 계획은 **기본 840 + 추가 9 = 최대 849개 논리 슬롯**이며 동일 fixed20 결과 4개 참조 시 최대 신규 계산 845건이다. 후보가 없거나 단계가 차단되면 이후 슬롯은 BLOCKED/미시작 사유로 남는다. 실제 비용 프로필이 없으면 COST_MODEL_UNVERIFIED로 최종 선정을 보류한다. 가상 30bp가 실제 수수료·세금·슬리피지를 검증했다고 주장하지 않는다. 실제 프로필에는 가상 비용을 중복 가산하지 않는다.

스냅샷을 딱 한 번 고정해 재사용하고 지표도 데이터/파라미터 해시로 캐시한다. 모든 전략×종목×기간을 한 배열에 쌓지 않는다. 실행 단위는 한 전략·한 구간의 **공동 계좌**이며 종목별 독립 계좌 합산으로 바꾸지 않는다. 기본 worker=1, 자원 측정 후 설정된 메모리 한도 내에서만 병렬화한다. 처리시간은 표본 측정 전 약속하지 않는다.

## 6. 기간 분리와 최종 한 개 선정

### 구간과 누수 통제

- 개발: 2015-01-02~2019-12-31에서 지표 준비 기간 제외.
- 검증: 2020, 2021, 2022, 2023 각 연도. 각 구간 계좌는 1억 원에서 새로 시작한다. 지표 준비 자료는 앞 기간에서 읽되 평가 전 거래를 이월하지 않는다.
- 잠금 제안: 2024-01-01~2026-09-10. 이전에 사용자가 이 구간으로 전략을 반복 선택한 이력이 있으면 미사용 구간으로 부를 수 없고 새 전진 기간을 지정한다. 선언만으로 미사용이 입증되지 않는다.
- 시작 전에 확정된 신호의 진입일이 첫 평가일이면 신규 진입을 허용한다. 종료일 미청산 포지션은 평가손익·미청산 수량을 표시하고 강제 이익 실현하지 않는다.

검증 구간은 후보 비교에 사용하므로 최종 성과의 독립 검증 구간이 아니다. 네 연도를 1억 원에서 반복 시작한 결과를 실제 연속 복리 계좌로 이어 붙이지 않는다. `product(1+R_year)-1`은 비교용 점수일 뿐 실제 계좌 수익률이 아니며 `validation_growth_score`로 이름 붙인다. 장기 연속 복리 실행은 선정 이후 별도 설명용 결과로 생성하고 840개 기본 슬롯에 포함하지 않는다.

### 1차 통과 기준: 모두 연구 제안이며 사전 고정

다음 게이트는 `selection_policy_v1`로 고정한다. 사용자 허용손실이 정해지면 **성과를 보기 전에** 버전 갱신한다. 임의로 문턱을 낮춰 원하는 전략을 통과시키지 않는다.

| 게이트 | 기준 |
| --- | --- |
| 데이터·장부 | EXECUTION_ELIGIBLE, 설명 안 된 키·평가·정산·현금 불일치 0 |
| 실행 완전성 | 해당 후보의 검증 16슬롯 전부 성공, 실패·누락 없음 |
| 표본 | 기준비용·지연1 네 해의 완료 거래 총 100건 이상, 표본 중복·상관 한계 표시 |
| 수익 | 기준비용 네 해 중 3해 이상 양수, validation_growth_score > 0 |
| 견고함 | 50bp와 지연2 각각 validation_growth_score > 0 |
| 위험 | 기준비용 네 해의 최대낙폭 최악값 ≤20% 제안; 10/20/30% 문턱별 통과 여부도 별도 표시 |
| 집중 | 기준비용 검증기간 총 양의 거래 손익 중 단일 종목 기여가 25% 초과면 부적격 제안 |

위 기준은 통계적 유의성이나 미래 수익을 보장하지 않는다. 100건은 독립표본 100개라는 뜻도 아니다. 가족별·연도별·비용별 결과와 양쪽 TP/SL 접촉 비율을 공개해 과최적화·일봉 체결 가정의 영향을 판단한다.

### 순위와 고정

통과 후보를 ① 기준비용 네 해 CAGR 중앙값 높은 순 ② 최악 최대낙폭 작은 순 ③ 연평균 회전율 낮은 순 ④ strategy ID 사전순으로 정렬한다. 임의 가중점수나 학습기간 최고수익으로 교체하지 않는다. 한 개의 기술전략을 `FROZEN_CANDIDATE`로 만들고 그 뒤 자금배분 정책을 같은 순서로 비교한다. 정책이 데이터·위험 기준을 통과하지 못하면 기본 fixed20을 유지하거나 선정 보류한다.

동일 후보·정책의 잠금 공통 4슬롯과 현실 비용 1슬롯에서 기본 비용 수익이 양수, 50bp·지연2 수익도 각각 양수, 현실 비용 결과도 양수이고 기준/현실 비용 최대낙폭이 사전 한도 내, 장부/평가 불확실성이 없어야 `SELECTED_FOR_PAPER_REVIEW`로 지정한다. 잠금 거래 30건 미만은 근거 부족으로 보류하는 제안이다. 실패하면 `NO_SELECTION`이며 **잠금 결과로 2등을 대신 고르지 않는다.** 새 가설은 새 실험 버전과 새 미사용/전진 검증이 필요하다.

모든 문턱과 후보 수를 기록해 시도 횟수를 숨기지 않는다. 낙폭·비용·희소거래·특정 종목 집중의 탈락 이유를 기계 판독 코드와 한국어 설명으로 함께 낸다. 최종 선정은 모의 검토 대상 선정이며 실전 주문 승인이 아니다.

## 7. 결과 저장과 상태 모델

상태는 `PLANNED → RUNNING → SUCCEEDED / FAILED / BLOCKED / CANCELLED`다. 프로세스가 죽어 heartbeat가 만료되면 `INTERRUPTED`로 표시하고, 원래 run을 덮어쓰지 않는 attempt로 재개한다. 0거래는 성공일 수 있지만 선정에는 부적격일 수 있다.

| 저장물 | 최소 필드/내용 |
| --- | --- |
| `experiment.json` | experiment ID, 전체 config·후보 목록·범위·seed, code/data/config hash, 실험 단계 |
| `registry.sqlite` | run ID·attempt·상태·시작/종료·진행률·오류 코드·산출물 경로·reuse_from |
| `signals.parquet` | signal ID, 종목 ID, decision_at, 알려진 데이터 cutoff, 진입군·파라미터 |
| `plans.parquet` | signal ID, 원화 entry cap·TP·SL, 기한, 수량 근거·예약, 위험/거절 사유 |
| `orders.parquet`, `fills.parquet` | 이벤트 ID·run·주문·수량·가격·비용·단계·부분/전량·취소·거절 |
| `positions.parquet`, `equity.parquet` | 일별 정수주·원가·현금·평가·TP/SL·노출·기간 초과·stale 상태 |
| `metrics.json`, `monthly.parquet` | 총수익/CAGR/Sharpe/MDD·월별 원화손익·적자월·노출·회전율·집중·미청산 |
| `artifacts.json` | 산출물별 행 수·스키마 버전·SHA-256, 완료 여부 |
| `leaderboard.csv`, `selection.json` | 모든 후보 순위/부적격/실패, 사전 정책·후보/정책 고정 해시·잠금 사용 기록 |
| `report.html`, `report.md` | 누적자산·낙폭·월별·전략군/비용/성장정책 비교와 최종 한 후보 또는 보류 이유 |

OHLCV 원본은 스냅샷 단위로 한 번만 보관한다. 각 run이 원본 전체를 복제하지 않는다. 모든 후보의 거래·결과를 저장하지만 중복 입력·지표·참조 결과는 content hash로 공유한다. 실패 run도 manifest·로그·완료된 단계의 검사값을 남기며 순위에서 조용히 삭제하지 않는다. CSV는 요약 교환용이고 대량 장부는 타입이 보존되는 Parquet를 사용한다.

임시 디렉터리에 산출물을 쓴 뒤 파일 해시 검증과 rename을 마치고 registry의 SUCCEEDED를 갱신한다. registry만 성공이고 파일이 없거나 해시가 다르면 CORRUPT로 차단한다. 동일 run ID의 중복 worker는 lease/고유키로 방지한다. code/config/data hash가 다르면 resume이 아니라 새 experiment다.

## 8. 계획하는 사용자 인터페이스

아래는 **전체 목표 CLI 계약**이다. `research.krx_lab` 모듈과 기본 실행 명령은 구현됐지만, 후속 `allocation`/`realistic-costs`/`holdout` 및 `freeze`/`finalize` 단계는 아직 차단한다. 현재 `--experiment`는 ID가 아니라 실험 디렉터리 경로를 받는다. 자동화의 목표는 plan/run/status/report/select/finalize를 통해 사용자가 후보별 명령을 직접 반복하지 않게 하는 것이다.

```text
python -m research.krx_lab plan --config <config.json> --out <new-directory>
python -m research.krx_lab run --experiment <id> --phase development,validation
python -m research.krx_lab status --experiment <id>
python -m research.krx_lab resume --experiment <id>
python -m research.krx_lab report --experiment <id>
python -m research.krx_lab select --experiment <id>
python -m research.krx_lab run --experiment <id> --phase allocation
python -m research.krx_lab run --experiment <id> --phase realistic-costs,ambiguity
python -m research.krx_lab freeze --experiment <id>
python -m research.krx_lab run --experiment <id> --phase holdout
python -m research.krx_lab finalize --experiment <id>
```

realistic-costs 단계는 잠금 전에는 검증4년만 읽고 잠금 비용1슬롯은 holdout 단계에서만 실행한다. ambiguity도 검증4년만 사용한다.

plan은 예상 후보·run 수와 data gate를 보여주며 대규모 실행 전 잘못된 설정을 잡는다. run은 앞 단계 검증을 강제하고 기본적으로 holdout을 포함하지 않는다. select는 잠금 데이터를 읽을 수 없고 freeze에는 기술 후보·정책·분석 버전·선정 규칙 해시가 필요하다. holdout 결과를 읽으면 사용 기록이 남고 재실행 이유·데이터 정정 이력을 보존한다.

## 9. 필수 검증과 구현 완료 기준

표준 검사는 합성 정답 장부와 실제 소량 고정 표본으로 수행한다. 결과값만 구현 코드와 똑같이 복제하는 검사는 피하고 독립 계산·사건별 정답·재시작 회귀를 사용한다.

| 검사 | 반드시 확인할 실패 사례 |
| --- | --- |
| 시간 | 미래 봉 추가가 과거 신호를 바꾸지 않음, 1월31일/윤년/휴일 월기한 |
| 가격 | 진입 전 TP/SL 값 존재, 갭 손절, 같은 봉 TP/SL, 당일 진입·청산, 호가 반올림 |
| 현금 | 정수주·비용·20슬롯 동시진입·자금 부족, intrabar 매도 현금의 시가 소급 사용 금지 |
| 재투자 | 입출금0, 수익/손실 후 다음 주문 규모, staged 상향·하향, 기준 미달 시 신규 진입 차단 |
| 데이터 | 거래정지·기업행사·0원·누락·상폐 정산, unresolved 결과의 선정 차단 |
| 배치 | 계획 슬롯 수, 중단/재개, 같은 manifest 재현, 손상 산출물, 실패/0거래의 전체 목록 유지 |
| 선정 | 동률·탈락·데이터 차단·NO_SELECTION, 잠금 접근 순서 위반, 잠금 실패 시 2등 대체 금지 |

규모 검사는 표본→한 전략 전기간→48개 개발→전체 검증 순서로 확대한다. 테스트 결과와 RSS·경과시간·디스크 사용량을 기록해 안전한 worker 수를 정한다. 소프트웨어 인수 통과와 시장 데이터 인수, 전략 선정 성공은 각각 다른 상태다. 구체적인 작업과 추적성은 [WBS](wbs.md), 기능별 인수는 [요구사항](requirements.md)을 따른다.
