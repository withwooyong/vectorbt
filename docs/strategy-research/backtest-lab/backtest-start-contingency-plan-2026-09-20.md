# 2026-09-21 백테스트 시작 판정과 ted-startup 비의존 대안

## 결론

**목적:** ted-startup의 최신 데이터 작업이 2026-09-21부터 `krx_lab`의 실자료 백테스트를 시작하기에 충분한지 확인하고, 충분하지 않을 때도 작업을 시작할 수 있는 경로를 정한다.

**현재 판정:** 내일부터 **전체 KOSPI·KOSDAQ의 의사결정용 백테스트는 시작할 수 없다.** 정식 `r4`가 없고 거래 상태 293건, 기업행사 505건, 가격계수 1,201건이 미해결이며 vectorbt의 REAL 실행 경로도 닫혀 있다. 대신 현재 로컬 후보에서 엄격하게 제외한 **807종목 제한 표본의 실가격 실행 리허설**은 준비할 수 있다. 첫 실행은 한 전략·한 연도로 제한해 신호·주문·장부·자원 사용을 확인한다. 이 실행은 전략 순위·수익성·최종 후보를 판단하는 근거로 사용하지 않는다.

**권장 책임 경계:** ted-startup을 앞으로의 필수 수집 담당으로 두지 않는다. 현재 파일은 한 번 고정해 초기 자료로 사용하고, 이후에는 별도 연구 데이터 프로젝트가 수집·정규화·revision 발행을 맡는다. vectorbt는 파일 인수, 제외 범위 결정, 전략 생성, 체결·장부, 결과 검증을 맡는다. 별도 프로젝트가 늦어지면 vectorbt는 고정된 제한 표본으로 엔진 작업을 계속한다.

**중요한 한계:** 807종목은 2015~2023 전체를 본 뒤 문제가 있거나 사건 기록이 있는 종목을 제거한 표본이라 생존편향과 미래정보 기반 제외가 있다. “기록된 사건 없음”도 사건 완전성을 증명하지 않는다. 따라서 이 표본에서 계산한 수익률은 연구 결론이 아니라 실행 경로 검증값이다. 2015년 이전 250봉이 없어 2015-06-15부터 모든 종목에 즉시 신호를 만들 수도 없다.

## 3. 기다리지 않고 사용하는 제한 표본

로컬의 r4 가격 후보를 읽기 전용으로 집계했다. 먼저 250봉 준비가 되는 2,780종목에서 다음 문제가 하나라도 있는 종목을 전 기간 제외했다.

1. 미확정 거래 상태가 있는 종목
2. 종류나 실행 상태와 관계없이 기업행사 기록이 하나라도 있는 종목
3. 판정과 관계없이 가격계수 변동 기록이 하나라도 있는 종목
4. 가격·수량 계수가 1에서 변한 적이 있는 종목
5. 원가격·조정가격 공급자가 다른 종목
6. 상장일, 재작성, 계수, 상태, 양수 가격, OHLC 관계 관련 중요 issue가 있는 종목

그 결과 **807종목·1,531,994행**이 남았다. 기간은 2015-01-02~2023-12-28이고 원가격·조정가격 공급자는 모두 키움으로 일치하며 남은 행의 상태는 모두 `TRADED`다. 이 숫자는 정식 데이터 revision이 아니라 현재 로컬 후보에 대한 재현 가능한 사전 집계다.

이 표본은 다음 목적으로만 사용한다.

- Parquet를 종목·기간 단위로 나누어 읽는 처리량과 메모리 측정
- 12개 진입 신호의 250봉 준비, 미래정보 차단, 연속 구간 분리 확인
- 4개 청산 규칙의 다음 시가 주문, 갭, 동봉 손절 우선, 월 만기 확인
- 1억원 공동현금, 최대 20종목, 정수주, 비용 차감과 원장 보존식 확인
- 48개 조합의 성공·실패·0거래 상태 및 재시작 검증

수익률 순위, 승률, 최대낙폭, 최종 전략 선정에는 사용하지 않는다. 표본 선정이 전 기간 사건을 사용했고 사건 자료의 완전성도 입증되지 않았기 때문에 결과에 `RESTRICTED_REAL_REHEARSAL`과 `SELECTION_PROHIBITED`를 강제로 기록한다.

또한 r4 universe에는 당시 업종 정보가 없다. 기존 실행기는 업종이 없으면 모든 종목을 `__UNKNOWN__`으로 묶고 25% 업종 한도를 적용하므로 의도한 최대 20종목 공동계좌가 되지 않는다. 리허설 runner는 이 차이를 명시적으로 기록하고, 전체 전략 비교 전에는 시점별 업종을 인수하거나 사전에 승인한 별도 리허설 규칙을 사용해야 한다.

## 4. 2026-09-21 실행 순서

### A. 오전 시작 전: 입력을 ted-startup에서 분리한다

현재 후보의 필요한 파일을 저장소 밖 `C:\Users\aeby\vscode\stock\vectorbt-data\krx-rehearsal\<revision>`에 복사하고 각 파일의 SHA-256, 원본 경로, 원본 revision, 복사 시각, 행 수를 manifest에 기록한다. 이후 실행 중에는 ted-startup DB나 작업 디렉터리를 다시 읽지 않는다.

복사 대상은 가격, universe, 상태 차단, 기업행사, 계수 대조, 공식 달력, 세금표와 준비일 파일이다. 인증키·토큰·운영 DB 정보는 복사하지 않는다. 원본이 바뀌면 덮어쓰지 않고 새 revision을 만든다.

### B. 1차: 한 전략·소형 기간으로 원장을 검증한다

`CROSS_5_20__PCT_3_6` 한 조합과 소수 종목으로 신호일 종가 → 다음 거래일 시가 → 손절/목표/만기 → 현금·보유 평가를 실행한다. 독립 계산한 거래 몇 건과 현금 보존식을 대조하고, 금지된 상태·미해결 사건·해시 변조 입력이 실패하는지 확인한다.

### C. 2차: 통과한 경우에만 48개 조합으로 확대한다

소형 검증과 자원 측정이 통과한 뒤 48개 후보를 2015~2019 개발 구간과 2020~2023 연도별 구간에 실행한다. 초기에는 기준 비용과 지연 조건만 실행하고, 자원 상한 안에서 10/30/50bp와 2일 지연 조건으로 확대한다. 업종·호가·비용이 실제 계약과 다르면 이는 의도한 48개 공동계좌 비교가 아니라 후보별 엔진 리허설이라고 결과에 표시한다. 모든 결과는 탐색 리허설 등급으로 저장한다.

### D. 종료 판정

다음 조건을 모두 만족하면 “실가격 백테스트 실행 경로가 시작됐다”고 보고한다.

- 입력 hash와 제한 기준이 결과 manifest에 남음
- 한 전략의 원장이 독립 계산과 일치함
- 중단 후 재개 결과가 처음부터 실행한 결과와 같음
- `select`, `freeze`, `finalize`, holdout 접근이 제한 등급을 거절함

48개로 확대했다면 성공·실패·0거래를 빠짐없이 기록하는 조건을 추가한다.

수익률이 좋아도 전체 시장 전략 선정 단계로 올리지 않는다.

## 5. vectorbt에 필요한 구현

현재 [`runner.py`](../../../research/krx_lab/runner.py)는 REAL 입력을 `REAL_EXECUTION_NOT_ADMITTED`로 거절한다. ted r3 manifest는 vectorbt C1 계약 형식도 아니어서 `inspect-real`에 직접 넣으면 `SCHEMA_INVALID:MISSING_FIELDS`가 발생한다. 현재 r3/r4 실가격 손익을 실행하는 CLI는 없다. 이 조건을 삭제하지 않고 다음의 분리된 경로를 추가해야 한다.

| 구현 | 완료 기준 |
| --- | --- |
| 전달 후보 → 로컬 고정 revision 도구 | 원본/사본 hash·행 수 대조, 덮어쓰기 거절, DB·네트워크 접근 0 |
| 제한 표본 builder | 위 6개 제외 규칙을 코드와 JSON 보고서로 고정, 종목·행 수 재현 |
| chunked signal adapter | 영구 `instrument_id`와 연속 활성 구간별 계산, 전체 종목×달력 프레임을 한 번에 만들지 않음 |
| `run-rehearsal` | 제한 revision만 허용, 실제 원가격 주문·조정가격 신호를 분리, 결과에 제한 등급 기록 |
| 리허설 시장 프로필 | 업종 누락·호가 1원 기본값·가상 bps 비용을 조용히 사용하지 않고 실제 계약과의 차이를 manifest에 기록 |
| 선택 금지 게이트 | `select`·후속 잠금 단계가 제한 결과를 항상 거절 |
| 소형 독립 원장 테스트 | 정수주·공동현금·비거래·갭·동봉 충돌·월 만기·비용을 사건별 기대값과 대조 |

기존 `run-delivery`의 합성 계약과 REAL 거절은 유지한다. 검증되지 않은 플래그 변경으로 실행을 우회하지 않는다.

## 6. 별도 데이터 프로젝트가 맡을 장기 경로

별도 프로젝트 이름은 예를 들어 `krx-research-data`로 두고 다음 계약만 책임지게 한다.

- 공급자별 원문과 수집 시각·요청 조건·hash 보존
- 원가격/조정가격·영구 종목 ID·유효기간·공식 달력 정규화
- 정지·재개·상폐·기업행사·단주 현금정산·가격/수량 계수 완결
- 날짜별 세금·수수료·호가·가격제한 규칙
- 불변 Parquet revision과 manifest·issue·admission 후보 발행

vectorbt는 이 프로젝트의 DB를 반복 조회하지 않고 발행된 로컬 Parquet만 읽는다. ted-startup은 자체 서비스 운영에 필요한 수집을 계속할 수 있으나 vectorbt의 일정 선행 조건으로 두지 않는다.

새 프로젝트가 늦어질 때는 다음 우선순위를 사용한다.

1. 제한 표본 리허설로 실행기·신호·원장·보고서를 계속 개발한다.
2. KRX 인증 표본과 이용 조건이 확보되면 별도 프로젝트에서 날짜별 가격·종목 정보를 검증한다.
3. 사건·상태·정산을 완결할 수 없으면 범위를 공식적으로 줄인 인수 revision을 만든다.
4. 전체 시장 정확성을 주장하지 않고, 인수된 종목·기간만 의사결정용 연구 후보로 승격한다.

KRX·증권사 API를 지금부터 새로 전수 수집하는 경로는 인증키, 과거 상폐 범위, 조정 정의, 사건·상태, 보관 권리를 아직 실측하지 못했으므로 09-21 시작의 주 경로가 될 수 없다.

## 7. 전체 시장 백테스트로 승격하는 조건

다음 조건을 모두 통과한 revision만 `EXECUTION_ELIGIBLE` 후보가 된다.

- 종목·날짜별 원가격과 신호용 조정가격의 의미·계수·원천 재현
- 당시 투자 가능 universe와 코드 재사용·시장 이전·상폐 이력
- 정지·재개·비거래 상태와 상폐 보유분의 실제 정산
- 분할·병합·증감자·합병·배당의 수량·현금·가격 계획 조정
- 공식 거래일과 날짜별 세금·수수료·호가·가격제한가

## 8. 확인 근거와 재현 범위

- ted-startup HEAD·브랜치·r1~r3 존재 여부와 r3 검증을 2026-09-20에 다시 확인했다.
