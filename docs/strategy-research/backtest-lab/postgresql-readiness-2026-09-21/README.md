# ted-startup PostgreSQL로 예정된 백테스트를 진행할 수 있는가

**판단: v3를 입력으로 백테스트 준비·구현을 진행할 수 있다. 그러나 현재 vectorbt 코드로 56개 전략의 실자료 성과를 바로 실행·확정할 수는 없다.** 운영 DB에 필요한 자료 묶음이 제공되었고, 현재 수정가격의 기본 OHLC 검사도 통과했다. 남은 핵심 작업은 vectorbt의 v3 인수·실행 연결, 신규 8개 전략, 비용·기업행사·무거래 처리 검증이다. ted-startup의 전면 재수집이나 업종 이력 확보를 이번 실험의 선행조건으로 추가할 근거는 없다.

2026-09-21 **16:18~16:20 KST**에 운영 DB를 읽기 전용으로 확인했다. 범위는 2014년 준비기간과 2015-06-15~2023-12-31 평가기간, 당시 KOSPI·KOSDAQ 보통주 정규장 일봉이다. 1억 원·최대 20종목, 기존 48개와 상대거래량 신규 8개를 합친 56개 비교가 최신 요청 범위다. 이번 점검은 성과 실행이나 전체 데이터 인수 승인이 아니다. 2024년 이후 잠금 가격은 조회하지 않았다.

아래에서는 먼저 공급 상태와 실행 가능 상태를 구분하고, 데이터의 확인 범위와 제한을 설명한 뒤 코드의 남은 작업 및 재현 근거를 제시한다.

## 3. 남은 품질 문제는 영향 범위를 구분해서 처리한다

**현재 소비 view에서는 과거 감사의 기본 수정가격 오류가 재현되지 않았다.** 현재 소비 view의 수정가격 4,574,759행에서 OHLC 결측, 0 이하 가격, 고가·저가 순서 위반은 각각 0건이었다. 거래량 0인 행은 71,109건이다. 과거와 소비 view·모집단이 다르므로 정정 효과를 직접 측정한 결과는 아니다. 기본 검사의 통과가 원가격과의 조정 재현, 전체 날짜 완전성, 기업행사 처리까지 증명하지는 않는다.

원가격에서는 OHLC 중 하나라도 0 이하인 행과 OHLC 순서 위반이 각각 135,717건이었다. 거래량 0인 행은 135,699건이고, **거래량 양수이면서 OHLC 중 하나가 0 이하인 행은 18건**이었다. 이는 전체 소비 범위의 집계다. 이전 인수인계의 1,891종목 부분집합·평가기간에서 나온 2건과 모집단이 다르므로 오류가 증가했다고 해석하면 안 된다. 이번에는 18건의 개별 키와 주문·보유 영향까지 판정하지 않았다.

인수 이슈에는 수정가격 부재 475건, 250봉 부족 306건, 미해결 기업행사 160건, 설명되지 않은 수정계수 1,061건이 있다. 또한 과거 가격 오류에 관한 REJECT 기록 301건과 업종 이력 제한 1건이 남아 있다. **이슈 기록에 남은 수정가격 오류 288건을 현재 v2 수정가격의 재현된 오류라고 보고하면 안 된다.** 이번 직접 집계에서는 해당 기본 오류가 0건이었다. 이슈의 출처·적용 범위를 현재 소비 키와 연결해야 한다.

미해결 기업행사·조정계수가 모든 전략을 자동 차단하는 것은 아니다. 다음 원칙으로 실행 범위를 확정한다.

- 수정가격이 없는 범위는 제외하고, 준비봉이 부족한 종목은 250봉이 확보된 이후부터 허용한다.
- 무거래·시가 0인 날에는 주문을 체결하지 않는다. 임의 가격 채움은 하지 않는다.
- 보유 중 행사·정지·상폐 등이 원화 현금과 주수에 미치는 영향이 미확정이면 해당 성과를 확정하지 않는다.
- 배당금은 이번 진입·청산 신호의 입력이 아니다. 수정가격 전략 비교와 실제 원화 정수주 계좌 성과는 구분한다.
- 업종 중립화·업종 로테이션에는 별도 업종 이력이 필요하지만, 이번 56개 실험은 업종 상한 없이 새 계약을 사용한다.

현 코드의 보수적 프로파일은 부적합 가격행 하나로 종목 전체를 제외할 수 있다. 이 정책이 만드는 생존·표본 선택 편향과 제외 종목·기간을 보고해야 하며, 이번 집계만으로 최종 사용 가능 종목 수를 확정하지 않았다.

## 4. vectorbt에 남은 구현

다음은 최신 소스에서 직접 확인한 실행 제약이다. 데이터 공급 완료와 별도로 해결해야 한다.

| 남은 작업 | 현재 코드 근거 | 완료 기준 |
| --- | --- | --- |
| v3 추출·불변 snapshot | `snapshot.py:21`은 구 `stock_price_krx` 수정가격 추출 | 11개 member·기간·원천 선택·해시를 묶은 로컬 Parquet 및 manifest |
| 56개 새 실험 계약 | `config.py:7,35`는 48개/v1 고정, 평가 시작 기본값도 과거 정책 | 2015-06-15 시작·56개·비용·배분·제외 정책을 결과 전에 고정 |
| 상대거래량 진입 2개 | `strategies.py:98`에 기존 12개 신호만 존재 | 20/60일 돌파 + 직전 20일 평균 대비 1.5배 거래량, 각 4개 청산 연결 |
| 업종 상한 제거 | `execution.py:378`은 업종별 25% 제한 | 새 실험에서 업종 정보를 요구하지 않도록 명시적 정책·회귀 검증 |

| 인수·실행 승인 연결 | `source_contract_admission.py:226`은 `execution_allowed=False` | 데이터 범위 승인(Gate A), 검증된 실행모델 승인(Gate B)과 실제 runner 결속 |

차단문 제거만으로 완료할 수 없다. 작은 실자료 실행에서 체결·수수료·세금·정수주·현금·기업행사 장부를 검증한 뒤 56개 개발·검증 구간으로 확대해야 한다. 고정 20종목과 종목별 독립 재투자 정책을 동일한 결과로 취급해서도 안 된다.

## 5. 추천하는 다음 단계

**vectorbt의 v3 어댑터와 새 56개 실행 계약 구현부터 진행하는 것이 적절하다.** DB의 부족 항목을 전부 정리할 때까지 대기하는 방식은 이번 최신 범위와 맞지 않는다. 먼저 사용 범위·제외 사유와 비용·체결 정책을 고정하고, 실제 신호·주문·보유에 영향을 주는 미확정 사례가 나오면 종목·날짜·필요 판정을 묶어 ted-startup에 요청한다.

이번 요청은 가능 여부 점검이므로 구현과 수익률 실행은 수행하지 않았다. 점검 완료와 전체 백테스트 완료는 별개다.

## 6. 검증 방법과 증거

- 두 SQL은 `REPEATABLE READ READ ONLY`, `ON_ERROR_STOP`, 조회 제한시간·잠금 제한시간을 적용하고 `ROLLBACK`으로 종료했다. 각각 독립 트랜잭션이며 완전히 같은 시점의 snapshot은 아니다.
- [메타데이터 SQL](metadata.sql), [결과](metadata/results.json), [실행 영수증](metadata/receipt.json).
- [소비 데이터 SQL](data.sql), [결과](data/results.json), [실행 영수증](data/receipt.json).
- 기존 `table-audit-2026-09-13/run_audit.py`를 재사용했다. 실행기 영수증의 `scope`는 기존 고정 문자열(2015 시작)이다. 실제 이번 조회 범위는 보존한 SQL과 결과 `context.scope`의 **2014-01-01~2023-12-31**이며, 영수증 원문은 변경하지 않았다.
- 등록 revision hash·가격 건수·가격 source record 최대값은 대조했다. **11개 member 전체 내용의 해시 재계산, 완전한 날짜별 가격쌍 대조, 최종 사용 종목 확정은 미실행**이며 snapshot 인수 단계의 필수 검증으로 남긴다. 소비 view는 신규 관측을 선택할 수 있으므로 이름이나 `SEALED` 메타데이터만으로 내용 불변을 가정하지 않는다.
- 독립 코드 검토에서 관련 회귀 **25 passed**: `test_source_contract_admission.py`, `test_real_admission.py`, `test_real_profile.py`, `test_integration.py`. 이는 프로파일·차단 동작 검증이고 실제 수익률 실행 성공이 아니다.
- 보고서 독립 검토에서 중요 미해결 지적은 없었다. 서로 다른 모집단 간 개선을 단정할 수 없다는 표현 지적과 코드 행번호를 반영했다. SQL·출력 해시, 집계 대조, 문서 링크·공백 및 `git diff --check` 검증을 통과했다.
- 전체 라이브러리 테스트·Rust·문서 사이트 빌드는 코드 변경이 없는 이번 점검에서 실행하지 않았다.

재현은 저장소 루트에서 기존 실행기에 `--sql`과 새 `--out` 디렉터리를 전달한다. 기존 출력 경로를 재사용하면 덮어쓰기 방지를 위해 실패한다.

```powershell
.venv/Scripts/python.exe -X utf8 docs/strategy-research/backtest-lab/table-audit-2026-09-13/run_audit.py core --sql docs/strategy-research/backtest-lab/postgresql-readiness-2026-09-21/data.sql --out <새-증거-디렉터리>
.venv/Scripts/python.exe -X utf8 -m pytest tests/research/test_source_contract_admission.py tests/research/test_real_admission.py tests/research/test_real_profile.py tests/research/test_integration.py -q
```

운영 상태·품질의 근거는 이번 DB 결과이며, 코드 판단의 기준은 [최신 인수인계](../handoff-v3-56-2026-09-21.md)와 `research/krx_lab/` 소스다. 전체 점검 진행 상태는 [WBS](wbs.md)에 기록한다.
