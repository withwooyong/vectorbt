**속도 판단:** 공개 명세상 KRX 4개 API는 날짜별 시장 자료를 요청한다. 이 점은 종목별 페이지 방식보다 호출 수가 적을 **가능성**을 뒷받침하지만, 인증 응답의 종목 수·서버 속도·누락·재시도를 측정하지 않았다. KRX 약관은 키당 1일 10,000회 이하를 정하고, 비상업적 이용·제3자 제공 금지·인증키 관리 조건을 둔다. 실제 응답 범위, 더 짧은 구간의 유량 제한과 이용 목적의 적합성을 확인한다. [KRX 약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp). 대량 파일 상품은 기간·필드·권리와 견적을 확인한 뒤 비교할 수 있다. 숫자로 된 완료 일수는 제시할 수 없다.

KRX 약관은 **이용기간 만료·해지 뒤 제공받은 정보의 이용도 금지**한다. 로컬에 저장했다고 무기한 재사용할 수 있는 것이 아니다. manifest에 서비스 승인 범위·만료일·이용 상태를 기록하고, 반복 실행 전에 권한이 유효한지 확인해야 한다. 내부 장기 연구에 필요한 저장·재사용·백업 범위는 약관과 별도 계약으로 확정한다. [KRX 약관 제5·11조](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp).

호출량은 표본 확인 뒤 `공식 거래일 수 × 실제 호출할 가격·기본정보 API 수 + 재시도`로 계산한다. **가령** 2014~2023을 약 2,500거래일로 가정하면 가격 2시장만 약 5,000회, 날짜별 기본정보 2시장까지 약 **10,000회**로 KRX 하루 한도에 닿는다. 이는 실제 거래일 수·응답 완전성·하루 완료 가능성의 확인값이 아니다. KIS의 100봉 한도로 4,000종목×2,500일×원/조정 2종을 전수 받는다면 이론상 **최소 200,000회**다. 토스 200봉이면 최소 100,000회다. 상폐·누락·재시도와 권한은 제외한 조건부 계산이다. 키움의 [공식 안내](https://openapi2.kiwoom.com/intro?dummyVal=0)는 국내 조회 초당 5회를 안내하며, KIS의 [유량 공지](https://apiportal.koreainvestment.com/community/10000000-0000-0011-0000-000000000001/post/d0d1a83f-6f8d-4437-9700-6d26702fd989)는 일반 실전 계좌 초당 18회를 안내한다. 신규 계정 제한과 서비스별 실제 한도는 별도 확인해야 한다.

## 3. 수집 순서: 소형 표본으로 정의를 고정한 뒤 연도별로 확대한다

1. **접근과 표본:** KRX 계정·인증키·유가/코스닥 서비스 승인 상태를 확인한다. 승인된 키로 2014년 지표 준비일, **2015-06-15**, 분할·배당·정지·상폐·코드 재사용 사례, 2023년 마지막 거래일을 각각 한두 날짜씩 요청한다. 응답 원문 바이트, 헤더의 비밀 아닌 항목, URL·요청 인자, 수신 시각, 상태 코드, SHA-256, 응답 건수·필드를 저장한다. 인증키·토큰은 파일에 남기지 않는다. KRX 응답의 주식/ETF 구분, 수정 여부와 종가 세션을 문서화한다.
2. **가격·우주:** 인증 표본과 이용 조건이 통과하면 KRX 유가/코스닥 일별 자료를 2014-01-01~2023-12-31 날짜별로 수집한다. 공개 명세에는 원가격·조정가격 정의가 없어 표본으로 확정하기 전에는 어느 쪽으로도 분류하지 않는다. 일별 종목기본정보가 과거 구성 종목을 재현하는지 확인한 뒤 보통주/상폐 종목/시장 이전/코드 재사용을 **별도로 검증한** 영구 식별자와 유효기간에 매핑한다. KRX 표준코드 자체가 기업행사·재상장 뒤에도 같은 기업을 가리키는 영구 ID라고 가정하지 않는다. 제공되지 않는 이력은 현재 마스터 값으로 소급하지 않고 `unknown`으로 기록한다. 실패·빈 응답은 공식 휴장·정지·결측 근거와 대조하며, 이어받기는 응답 해시/완료 manifest 기준으로만 한다.
3. **교차 확인·조정가격:** 키움 ka10081과 KIS 기간별 일봉은 먼저 20~30개의 고정 사례에서 원가격·조정가격·분할 전후·상폐 접근 가능성을 확인한다. 토스도 계정/권한이 있으면 같은 사례를 시험한다. 서로 다른 날짜의 조정 기준으로 받은 조정계열을 한 열에 섞지 않는다. 신호용 조정가격은 기준일·소스·변환·사건 연결이 명확한 구간만 만들고, 원가격 주문·정수주 장부와 분리한다.
4. **사건·상태:** OpenDART/KIND의 공시 ID, 접수·발표 시각, 효력일, 정정/취소 관계와 원문 해시를 저장한다. 확인한 KRX 4개 API에는 정지·상폐 상태 필드가 없으므로 **별도 공식 상태 자료의 제공 범위를 검증한 뒤** 상장·폐지·정지·재개와 기업행사를 시점별로 연결한다. 공시 누락 가능성이 남으면 그 기간·종목을 `BLOCKED`로 둔다. 공식 거래일·임시 휴장·단축장, 호가단위·가격제한가 규칙, 날짜별 세금과 실제 증권사 수수료도 별도 출처로 확인한다.
5. **고정 revision:** 연도·시장별 파일을 만든 뒤 유일키·OHLC 관계·양수 가격·원/조정 계수·상태별 기대 행·원천 간 차이를 검사한다. 문제를 숨기기 위해 0원/결측을 전일 값으로 채우거나 일방적으로 삭제하지 않는다. 소형 원장 표본을 독립 계산과 대조하고 **인수 가능한 기간/종목만** `admitted`로 분리한다. 같은 데이터를 여러 번 백테스트할 때는 이 고정 로컬 revision만 사용한다.

현재 `snapshot.py`는 ted-startup PostgreSQL의 수정가격을 SSH로 읽어 로컬 Parquet로 만드는 경로다. 위 직접 수집은 **새 source adapter와 별도 manifest**가 필요하다. 기존 [`local_slice.py`](../../../research/krx_lab/local_slice.py)는 해시 검증된 로컬 스냅샷의 기간·종목·열 선택에 참고할 수 있으나 ted 전달본과 새 스키마를 자동으로 같은 등급으로 취급하지 않는다. 현재 [`runner.py`](../../../research/krx_lab/runner.py)의 REAL 실행 차단도 유지한다.

## 4. 저장은 원문 파일 + 로컬 Parquet가 중심, DB는 선택적 색인이다

반복 연구가 네트워크 조회에 매이지 않도록 **저장 위치는 저장소 밖의 접근 제한된 로컬 디렉터리**로 제안한다. 예시: `C:\Users\aeby\vscode\stock\vectorbt-data\krx-daily\<dataset-id>\<revision>\`. 이 경로는 아직 생성하지 않았으며 실제 용량·백업 위치·사용권 확인 후 정한다. 인증키와 원문 시세는 git에 넣거나 외부에 재배포하지 않는다. 저장소에는 코드·스키마·예제 manifest만 둔다.

```text
<revision>/
  raw/<provider>/<endpoint>/<yyyy>/<yyyymmdd>/<request-id>.json[.gz]
  normalized/prices_raw/market=<market>/year=<yyyy>/part-*.parquet
  normalized/prices_adjusted/source=<provider>/basis=<basis>/year=<yyyy>/part-*.parquet
  normalized/instruments/, events/, statuses/, calendar/, costs/
  issues/row_issues.parquet
  manifest.json
  admission.json
```

`manifest.json`에는 dataset/revision, 이전 revision, 수집 코드·설정 hash, 출처·URL·요청 모드, 취득 시각, **서비스 승인·이용 만료일**, 각 파일의 bytes/행 수/SHA-256, 조사한 가격·세션 정의를 넣는다. 허용된 기간에는 원문을 append-only로 보존하고 정규화 결과를 새 revision으로 재생성한다. 필요하면 SQLite 또는 DuckDB로 수집 작업 큐·파일 색인을 만들 수 있으나, **권한이 유효한 전략 반복 실행의 입력은 로컬 Parquet**로 고정한다. PostgreSQL은 다중 사용자 조회·운영 연계가 실제로 필요할 때만 추가한다. 저장 형식은 출처 근거를 대신하지 않으며 `admission.json`은 원천·시장 규칙·원장 검증을 통과한 범위만 명시한다.

## 6. 지금의 결정은 전수 수집 보류이며 인증 표본·계약·사건 범위가 다음 관문이다

**현재 결정:** ted-startup 없이 **모든 필수 데이터를 정확하고 빠르게 확보할 수 있다는 근거는 없다.** KRX 무료 Open API 4개는 공개 명세상 가격과 날짜별 기본정보까지이며, 기업행사·거래정지·상폐 정산·조정계수·날짜별 비용을 제공한다는 근거가 없다. 특히 전수 종목·상폐 보존과 가격 의미는 인증 응답이 없어 미검증이다. 키움·KIS·토스의 종목별 일봉도 이를 자동으로 채우지 않는다. 따라서 기존 ted `r2`를 대체할 신규 전체 데이터셋 제작이나 REAL 차단 해제 일정을 확정하지 않는다. 이 감사가 확인한 것은 **의존하지 않는 수집 경로를 시험할 수 있는 후보**뿐이다.

**다음 검증 순서:** (1) KRX 승인 키와 유가/코스닥 가격·기본정보 4개 서비스 승인, 보관·재사용 조건을 확인한다. (2) 2015-06-15 및 분할·상폐·거래정지·코드 변경 고정 표본을 인증 조회해 응답 원문·필드·건수·표준코드 결합률·원/조정·정규장 의미를 기록한다. 표준코드와 영구 기업 ID의 관계도 별도 검증한다. (3) 사건·상폐 정산·당시 업종·호가/비용의 **완전한** 제공 경로를 확인한다. KRX 유료 상품이 필요하면 필드·기간·계약·비용 견적을 받아 비교한다. (4) 그 결과가 통과하면 소형 종목/짧은 구간을 저장해 독립 원장으로 검증하고, 이후에만 연도별 전수 수집·48개 후보를 검토한다. 어느 관문이 실패했는지 기록하고 범위를 임의로 확정하지 않는다.

**필요한 접근:** KRX 비상업적 API 약관이 이 내부 연구에 맞는지, 증권사·토스의 계정/API 권한과 데이터 보관 조건, KRX 파일 상품 구매의 비용·기간은 사용 조건을 확인해야 한다. 현재 환경에는 해당 인증키가 없어 인증 표본을 실행할 수 없었다. 외부 서비스에 대한 키 발급·유료 구매·대량 호출은 이 문서에서 실행하지 않았다. API/스크래핑 경로의 존재만으로 재배포 권리나 장기 보관 권리를 추정하지 않는다.

**실행 차단 요인:** 2015년 당시의 종목/상태·기업행사 전수와 조정계수 원천, 상폐 보유분의 실제 정산, 날짜별 비용/호가가 완성되지 않으면 전체 시장의 정확한 수익률은 `BLOCKED`다. KRX나 증권사 표본이 이 공백을 채우지 못하면 KRX 유료 일괄 파일과 사건 상품의 제공 범위를 문의하거나 제한된 종목·기간의 검증 가능한 연구로 범위를 줄인다. [기존 데이터 전달 명세](remediation-discovery-2026-09-14/delivery-spec.md), [KRX 데이터 구입안내](https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA001.jsp).

**검증 범위:** 2026-09-19 KRX 네 공식 API 페이지의 내장 개발 명세, 무인증 표본의 HTTP 401, 증권사·공시 공식 문서와 현재 저장소 코드를 확인했다. API 키로 실응답을 호출하거나 속도·전체 종목 완전성·사용권 적합성·실제 수익률은 검증하지 못했다. KRX 공개 개발 명세의 서버 SQL은 거래일이 종목 메타 유효기간 안에 있는지 결합하지만, 이 설계가 실제 과거 상폐 종목을 빠짐없이 반환하거나 당시 발표된 정보만 재현한다는 증거는 아니다. 제공처별 확정 판정은 인증 표본 원문·해시와 이용 조건을 확보한 뒤에만 갱신한다.
