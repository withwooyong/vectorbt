# KRX 일봉 백필 인수 기준

이 문서는 별도 프로젝트가 수행할 2015-01-02 이후 KRX 일봉 백필을 이 연구에서 사용할 수 있는지 판정하는 계약이다. 핵심 결론은 시작일 도달이나 채움 비율만으로는 인수할 수 없다는 것이다. 날짜별 역사 유니버스, 가격 조정 근거, 거래정지·상장폐지·기업행사, 단위와 재현 가능한 적재 명세까지 함께 통과해야 한다.

범위는 연구용 데이터의 읽기 전용 검증과 인수 판정이다. 원본 DB 변경, 수집 실행, 공급자 선정은 포함하지 않는다. 외부 공식 거래일 달력과 시점별 종목 유니버스가 현재 없으므로 “기대 행 대비 100%”인 진짜 완전성은 그 자료가 납품되기 전에는 판정할 수 없다.

## 핵심 판정

인수 상태는 아래 셋 중 하나만 사용한다.

| 상태 | 의미 | 연구 사용 |
| --- | --- | --- |
| `PASS` | 필수 산출물과 P0/P1 검사가 모두 통과하고 재현 가능함 | 합의한 전략군의 본 성과 산출 가능 |
| `RESEARCH_ONLY` | 가격 탐색·코드 검증에는 쓸 수 있으나 편향 없는 성과 주장은 불가함 | 진단과 예비 실험만 가능 |
| `BLOCKED` | 키 무결성이 깨지거나 가격 의미가 불명확하여 수익률 계산 자체를 정의할 수 없음 | 숫자 성과 산출 금지; 스키마·품질 진단만 가능 |

현재 기준선은 진단·구현 준비 범위의 `RESEARCH_ONLY`다. 조정가의 내부 품질은 일부 확인됐지만 과거 유니버스와 조정 계보가 없어 생존자 편향 및 미래정보 사용을 배제할 수 없다. 예비 수익률 숫자를 내기 전에도 조정가격 정의 확인이 필요하며, 정의가 불명확하면 그 실행은 `BLOCKED`다. 원가격·기업행사·정수 주수 요건은 실험 명세의 E3 운용 검증에 적용한다.

같은 데이터의 사용 가능 여부는 단계에 따라 아래처럼 구분한다. 현재 `RESEARCH_ONLY`는 E2 실행 승인이 아니다.

| 사용 단계 | 현재 사용 가능 여부 | 해제 조건 |
| --- | --- | --- |
| E0 스키마·품질 진단 | 가능, 이번 작업에서 실행 | 읽기 전용 유지 |
| E1 조건 계산·대조 | 계산 정의 작성 가능, HTS 대조 미실시 | HTS 동일 시점 결과와 가격·단위 확인 |
| E2 예비 수익률 비교 | 미실행, 현재 보류 | 조정가격 비율 의미와 조건 일치 확인; 현 종목 편향을 표시한 제한 범위만 허용 |
| E3 실제 운용·역사 유니버스 검증 | 차단 | 원가격·기업행사·역사 종목·거래 상태·비용 게이트 통과 |

## 판정 순서와 심각도

먼저 P0으로 데이터의 정체성과 재현성을 확인하고, P1으로 편향 없는 백테스트 가능성을 확인한다. P2는 설명·운영 품질이며 단독으로 결과를 막지는 않지만 미해결 내용을 manifest에 남겨야 한다.

| 등급 | 실패 의미 | 처리 |
| --- | --- | --- |
| P0 | 같은 입력으로 같은 가격을 만들 수 없거나 수치 무결성이 깨짐 | 즉시 `BLOCKED` |
| P1 | 거래 가능 종목·일자 또는 체결 가능성을 시점 기준으로 판정할 수 없음 | 본 검증에 인수 불가; 범위를 밝힌 탐색만 `RESEARCH_ONLY` |
| P2 | 설명, 표본 대조, 운영 기록이 불충분함 | 보완 전 조건부 인수, 제한을 결과에 명시 |

## 필수 납품 필드와 산출물

다음은 본 검증 PASS를 위한 정보 계약이며 테이블명은 아니다. 정규화 방식은 달라도 각 값의 의미와 시점 기준이 같아야 한다. 원가격·조정계보가 없는 예비 연구는 PASS가 될 수 없지만, 조정가격의 비율 의미를 확인한 뒤 E2로 한정할 수 있다. P0의 값 불일치는 BLOCKED이며, E3 전용 산출물 미납은 E3 차단과 RESEARCH_ONLY로 구분한다.

| 영역 | 최소 필드 또는 산출물 | 필수 의미 | 등급 |
| --- | --- | --- | --- |
| 가격 | 영구 종목 ID, 거래일, raw OHLC, 조정 OHLC, 거래량, 거래대금 | raw와 adjusted를 구분하고 가격·수량·금액 단위를 명시 | P0 |
| 조정 계보 | 종목 ID, 효력일, 행사 유형, 가격 계수, 수량 계수, 출처·버전 | 어떤 기업행사가 어느 과거 값에 반영됐는지 재계산 가능 | P0 |
| 역사 유니버스 | 종목 ID, 유효 시작·종료일, 당시 시장·상품 유형, 상장 상태 | 날짜별로 그날 알려진 거래 대상 집합을 복원 | P1 |
| 상태 이력 | 상장일, 상장폐지일, 거래정지·재개 구간과 사유 | 무거래와 결측을 구별하고 상폐 종목을 보존 | P1 |
| 기업행사 | 분할·병합·유상/무상증자·배당·권리락·합병·종목코드 변경 | 수익률 단절과 종목 연결을 설명 | P1 |
| 거래일 | 시장, 거래일, 개장 여부, 임시 휴장·단축장 표시 | 기대 행의 분모를 외부 기준으로 계산 | P1 |
| manifest | 실행 ID, 소스, 추출 시각, 범위, 행 수, 스키마 버전, 파일/배치 해시 | 재실행·수정 이력·납품 동일성 확인 | P0 |
| revision | 실행 ID, 변경 키 수, 변경 사유, 이전/이후 해시 | 공급자 정정과 재백필을 추적 | P0 |

식별자는 현재 `stock.id`만 전제로 삼지 않는다. 코드 재사용이나 코드 변경을 고려한 영구 ID 및 매핑 이력이 필요하다. 시장 분류도 현재값 하나가 아니라 유효기간을 가진 당시 값이어야 한다.

## 필수 인수 게이트

### 1. 범위와 유니버스

- 납품 시작은 2015-01-02이나, 지표 lookback에 필요한 warmup은 그보다 앞서 제공한다. 제공하지 못하면 가장 긴 lookback과 신호 지연을 반영해 성과 시작일을 늦춘다.
- “현재 종목 역채움”과 “당시 존재했던 종목의 역사 유니버스 복원”을 별도 집계한다. 전자만 완료한 결과는 `RESEARCH_ONLY`다.
- 상장폐지, 이전상장, 종목코드 변경, 신규상장을 포함한 날짜별 포함/제외 사유를 납품한다.
- `market_code='0'`은 현재 ETF 등도 포함하므로 코스피 보통주와 동의어로 쓰지 않는다. 당시 시장과 상품 유형으로 대상을 필터링한다.
- 외부 거래일 달력과 역사 유니버스를 기준으로 `expected`, `observed`, `missing`, `not_expected`를 분리한다. 이 분모 없이 시작일 도달률이나 100% 비율을 완료 근거로 쓰지 않는다.

### 2. 가격·조정·체결 모형

- raw 가격과 조정계수 또는 기업행사 원장을 보존하고, 조정가 생성식·반올림·소급 범위·재수정 정책을 문서화한다.
- raw→adjusted 재계산 표본이 납품값과 합의 오차 내에서 일치해야 한다. 가격 단위, 거래량 단위, 거래대금 단위를 원천 명세와 대조한다.
- 백테스트는 정수 주수, 주문 가격 시점, 수수료·세금·슬리피지, 거래정지·가격제한·상폐 잔존가치 처리를 명시해야 한다.
- 조정가만으로 수익률을 계산하면서 별도 배당 현금흐름을 중복 반영하지 않는다. 기업행사 모형이 확정되지 않으면 성과 연구는 `BLOCKED`다.
- 거래량 0은 자동 오류가 아니다. 거래정지·무거래·원천 표기와 대조하며, 체결 가능성은 0으로 처리할 규칙을 정한다.

### 3. 무결성 및 완전성 허용치

| 검사 | 허용치 | 근거와 실패 처리 |
| --- | --- | --- |
| `(영구 종목 ID, 거래일, 가격 종류)` 중복 | 0 | 한 시점 값이 둘이면 결과가 비결정적이므로 P0 |
| 고아 가격 키 | 0 | 종목 정체성을 확인할 수 없으므로 P0 |
| OHLC null·0 이하·고가/저가 관계 위반 | 0 | 일봉 수익률과 체결 가격이 정의되지 않으므로 P0 |
| 음수 거래량·거래대금 | 0 | 명시된 보정 부호가 아니라면 단위 계약 위반이므로 P0 |
| 기대 거래 종목일의 설명 없는 누락 | 0 | 공식 달력·역사 유니버스·정지 이력 결합 후에만 적용하는 P1 |
| manifest 해시 불일치 또는 미기록 revision | 0 | 검증한 납품과 사용한 납품의 동일성을 보장할 수 없어 P0 |

0 허용치는 분석에 투입하는 유효 가격 행에 적용한다. 공급자가 정지일을 0/NULL 가격으로 제공하면 원본은 보존하고 상태·제외 사유를 기록해 분석용 행과 분리한다. 경제적으로 유효한 0 거래량이나 공식 비거래일을 결측으로 세지 않는다. `listed_date` 이전 행도 즉시 오류로 단정하지 않고 이전상장·코드 승계·마스터 날짜 의미를 원천 이력으로 설명하게 한다.

### 4. 표본 대조와 재현성

- 대형주, 소형주, ETF, 신규상장, 상폐, 장기정지, 분할·배당·코드 변경을 포함한 고정 표본을 원천과 대조한다.
- 시작·종료 경계와 기업행사 전후 값을 비교하고, 표본 선정 규칙과 원천 응답 해시를 남긴다.
- 같은 소스 버전과 설정으로 재실행한 행 수·키·내용 해시가 같아야 한다. 달라지면 revision 기록으로 차이를 설명한다.
- 아래 읽기 전용 SQL 결과와 manifest 요약을 함께 보관한다. SQL의 내부 날짜 간격 검사는 현재 관측된 날짜를 쓴 대리 지표이며 공식 완전성 증명은 아니다.

## 현재 기준선: 2026-09-10 관측

- `adjusted=true`만 4,481,979행, 4,505종목이며 관측 범위는 2015-04-03~2026-09-09다. raw 가격과 조정계수는 현재 스키마에서 확인되지 않았다.
- 1,804종목이 모두 812행이고 2023-05-11에 시작한다. 대표 표본 `005930`, `000660`, `069500`도 같은 날부터 812행이어서 일괄 적재 경계를 의심할 근거가 있으나 원인은 미확정이다.
- 현재 `listed_date`보다 앞선 가격이 41,977행이다. 이는 날짜 의미, 이전상장, 코드 승계 가능성을 확인할 조사 대상이지 곧바로 오류 수량은 아니다.
- 거래량 0은 173,158행이다. 음수·null 거래량은 0행이며, 0 거래량은 정지 이력이 없어 정상 무거래와 구별할 수 없다.
- 중복 키, 고아 가격, null/비양수/관계 위반 OHLC, 관측 구간 내부의 대리 달력 기준 gap은 0으로 집계됐다.
- 현재 시장 membership는 현재값이고 `market_code='0'`에 거래소·ETF·기타 상품이 섞여 있다. 시점 기준 시장 membership, 상장폐지·정지·기업행사 이력은 부재하거나 확인되지 않았다.

따라서 현재 데이터는 가격 코드 개발에는 사용할 수 있지만, 2015년부터의 전체 코스피 성과나 생존자 편향 없는 비교를 주장할 수 없다.

## 담당자에게 전달할 작업 요청

## 읽기 전용 재검증

검사는 [01-schema.sql](sql/01-schema.sql), [02-data-audit.sql](sql/02-data-audit.sql), [03-coverage.sql](sql/03-coverage.sql), [04-backfill-check.sql](sql/04-backfill-check.sql)을 사용한다. PowerShell 7에서 한글 출력이 손상되지 않도록 콘솔과 PostgreSQL 클라이언트 인코딩을 UTF-8로 고정한다.

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$auditOutput = Join-Path 'docs/strategy-research/evidence' (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory -Path $auditOutput | Out-Null
$checks = @('01-schema', '02-data-audit', '03-coverage', '04-backfill-check')
foreach ($check in $checks) {
    $auditResult = Get-Content -Raw -Encoding utf8 "docs/strategy-research/sql/$check.sql" |
        ssh -o BatchMode=yes -o ConnectTimeout=8 home "docker exec -i -e PGCLIENTENCODING=UTF8 kiwoom-db psql -X -U kiwoom -d kiwoom_db -P pager=off" 2>&1
    $auditExit = $LASTEXITCODE
    $auditResult | Set-Content -LiteralPath (Join-Path $auditOutput "$check.txt") -Encoding utf8
    if ($auditExit -ne 0) { throw "$check failed: $auditExit" }
}
```

사용자가 제공한 `home` SSH 별칭으로 서버 가동시간에 실행하며 기존 증거를 덮어쓰지 않는다. 각 결과의 읽기 전용 트랜잭션, 관측 시각, 실행 종료 성공을 확인한 뒤 이전 기준선과 diff한다. 최종 `PASS`는 이 SQL의 0건 조건뿐 아니라 외부 달력·역사 유니버스 기반 기대 행 검증과 가격 조정 재계산까지 통과했을 때만 부여한다.
