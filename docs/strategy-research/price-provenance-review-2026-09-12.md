# 종가 0 원인 추적과 데이터 사용 판정

이 문서는 `102950`의 종가 0 문제를 어디까지 설명할 수 있는지 판정한다. **현재 배포 코드의 정수 변환·저장 경로는 확인했지만 원천 응답이 없어 원인은 미확정이며, 전체 테이블의 E2/E3 수익률 실행은 계속 `BLOCKED`다.** 2026-09-12 22:20 KST 읽기 전용 DB 관측 기준이다. HTS 표본 계산 준비는 가능하며 실제 조건 일치는 별도 검증이다.

먼저 아래 판정과 추가 자료를 확인한다. 뒤의 코드·DB 증거는 원인을 좁히는 근거이며 공급자 오류나 거래정지를 확정하는 근거는 아니다.

## 다음 조치는 원천 표본과 실행 기록 확보다

| 판단 대상 | 확인한 사실 | 판정 |
| --- | --- | --- |
| 가격 무결성 | 8,202,637행·4,506종목, 종가 0인 1,201행 유지 | 전체 테이블 수익률 실행 차단 유지 |
| 로컬 정수 변환 | 문자열에 `int()` 적용. `"0.4"`는 0이 아니라 `None`; `"0"`은 0 | 이 함수의 소수점 절삭으로 0이 생겼다는 가설은 지지되지 않음 |
| 저장 경로 | 날짜 sentinel만 제외하고 정규화 가격을 upsert | 원천 0이 들어오면 보존되는 경로는 존재 |
| 원천 응답 | `raw_response`의 `api_id='ka10081'` 보관 건수 0 | 과거 원천→DB 직접 대조 불가 |
| 공급자 라벨 | `data_vendor='KIWOOM'`; migration 022는 기존 행에도 이 기본값 사용 | 실제 개별 적재 출처를 독립적으로 입증하지 못함 |
| 백필 완료 | 담당 저장소 HANDOFF는 실패 0·약 95분 완료를 기록 | 담당 기록은 확보했으나 실행 ID·완료 로그·해시 manifest 미확보 |

**추가 자료 요청안:** 백필 담당 프로젝트에서 `102950`의 2015-01-02, 2019-11-26~27, 2019-12-02 및 기업행사 전후에 대해 당시 수정/미수정 원천 응답, 요청 기준일·플래그, 변환 전후 가격, 거래량 단위와 거래 상태를 제공한다. 실행 ID·시작/종료·성공/실패·대상 범위·실행 코드 해시와 원천 응답 해시를 함께 남긴다. 지금 재조회한 원천은 당시 원천과 구분하고 소급 정정 가능성을 기록한다. 이 요청안은 문서로만 작성했으며 외부 전송하지 않았다.

원천도 0이고 조정 반올림으로 설명되면 원가격과 조정계수 또는 정밀 조정가격을 확보한다. 원천이 양수인데 DB가 0이면 담당 프로젝트에서 적재 변환을 수정하고 revision을 남겨 재납품한다. 공식 비거래 상태로 설명되면 원본을 보존하고 상태·제외 사유를 가진 분석용 행을 정의한다. 어떤 경우든 임의 전일 값 채우기나 종목 전체 제외만으로 인수 완료를 선언하지 않는다. 양수인 1원 구간도 가격 정밀도 검토 대상이다.

## 0원 이후 1원 구간은 조정 정밀도 조사 단서다

DB 마스터에서 `102950`은 아하, 현재 `is_active=true`, `listed_date=2022-11-30`이다. 이 현재 상장일만으로 2015년 가격을 오류로 단정하지 않는다. 과거 시장·종목 승계 이력을 별도로 확인해야 한다.

- 종가 0은 2015~2018년 각각 248·246·243·244행, 2019년 220행으로 합계 1,201행이다. 거래량 양수인 종가 0은 합계 695행이다.
- 2019-11-26에는 종가 0·거래량 22,472,500, 11-27에는 시가·고가 1과 저가·종가 0이 함께 저장됐다. 12-02~06 표본의 OHLC는 모두 1이다.
- 표본 과거 행의 `created_at`, `fetched_at`, `updated_at`은 2026-09-10 21:29:04 KST로 같다. 이 값은 DB 적재 시각이며 공급자 추출 시각이나 실행 ID를 대신하지 않는다.

**해석:** 0/1 가격과 양수 거래량의 조합은 조정계수·반올림을 조사할 이유다. 원천 오류, 가격 조정, 거래 상태 중 어느 원인인지는 아직 구분하지 못했다. 특히 양수 거래량 695행을 단순 무거래로 처리할 수 없다.

## 현재 코드와 과거 실행 코드는 구분한다

로컬 `ted-startup` HEAD는 `5a72bae458f92471a67ce2e3d95f257271246c6e`, 서버 체크아웃 HEAD는 `e2d51f7f876949d967a5a1f55e539cec672b62e5`였다. 아래 5개 파일은 로컬 줄바꿈을 LF로 정규화한 SHA-256과 실행 중인 `kiwoom-app` 파일 해시가 모두 일치했다. 이는 현재 코드 일치이며 과거 백필 당시 코드 일치까지 입증하지 않는다.

경로 기준은 `ted-startup/src/backend_kiwoom/`이다.

1. `scripts/backfill_ohlcv.py`: 일봉 ingest use case 사용.
2. `app/application/service/ohlcv_daily_service.py`: 조회와 정규화에 `adjusted=True` 전달.
3. `app/adapter/out/kiwoom/chart.py`: 요청 `upd_stkpc_tp="1"`, `cur_prc`를 `_to_int`로 변환.
4. `app/adapter/out/kiwoom/stkinfo.py`: 쉼표 제거 후 문자열 정수 파싱, 잘못된 값은 `None`.
5. `app/adapter/out/persistence/repositories/stock_price.py`: 정규화 가격을 저장하며 0 가격을 별도로 거르지 않음.

`migrations/versions/022_delisted_stock.py`의 `data_vendor` 기본값도 읽었다. 기존 HANDOFF의 `source` 컬럼 예정안과 현재 구현 이름은 다르므로 최신 스키마를 기준으로 한다. 담당 저장소 문서는 현재 DB·코드와 대조할 주장으로 취급했다. 다른 저장소와 서버에 변경을 가하지 않았다.

## 수정주가의 경제적 의미는 여전히 추가 확인이 필요하다

공식 [키움종합차트 도움말](https://download.kiwoom.com/hero4_help_new/0600.htm)의 차트환경설정은 증자·감자 등 자본 변화에 따른 가격 재산출을 설명한다(2026-09-12 확인). 이 설명만으로 REST 일봉과 HTS 조건검색의 조정 방식 동일성, 현금배당 포함 총수익률, 원 단위 반올림, 소급 정책을 확정할 수 없다. [REST 안내 페이지](https://openapi.kiwoom.com/m/guide/apiguide?dummyVal=0)는 열렸지만 이번 열람에서 `ka10081`의 세부 조정 정의를 확보하지 못했다.

가격 정의가 확정되기 전에는 `adjusted=True`가 같은 두 공급자의 시계열을 동일 기준으로 합치지 않는다. 새 `data_vendor` 라벨이 생겨도 가격 조정 계약이 자동으로 충족되지는 않는다.
