# 키움 조건검색 기반 전략 연구

## 최신: 연구 프로그램 구현·실제 데이터 실행 판정

[Backtest Lab 설계 패키지](backtest-lab/README.md)부터 읽는다. 사용자는 최대 달력 1개월 보유, 매수 전 익절·손절 지정, 초기1억·인출0·재투자와 외부 여유자금1~2억 분리를 명확히 했다. PRD·요구사항·48개 후보 전략 명세·기술 명세·WBS를 작성했다. 연구 엔진과 일괄 저장·검증 CLI를 구현했다. 실제 DB 2015~2023년 610만 행을 추출했으나 데이터 인수 실패로 성과 실행과 전략 선정은 보류했다. [구현·실행 결과](backtest-lab/implementation-and-results-2026-09-13.md)에서 완료 범위와 명령을 먼저 확인한다. 이전 2~5일 중심 권장은 폐기한다.

이 폴더는 홈서버의 국내주식 일봉으로 기술전략을 비교하고, 선정 전략을 뉴스 결합 자동 모의투자·실전투자로 확장하기 위한 연구 자료다. **2026-09-13에 실행 안내·연구용 예제·자동매매 설계·오픈소스 비교를 추가했다.** 사용자는 PostgreSQL에 2015-01-02부터 적재했다고 확인했다. 실제 데이터의 수익성·HTS 일치·모의 및 실전 주문은 아직 검증하지 않았으며, DB는 13:07 KST 연결 복구 후 14:12 KST에 8,789,127행·5,011종목·2015-01-02~2026-09-10을 읽기 전용으로 확인했다. 종가 0인 1,201행은 남아 있어 데이터 인수는 미완료다.

## 먼저 읽을 최신 실행 안내

후속 자동매매 목표인 최대 약 20종목·1개월 이내 스윙, 실시간 검색→AI 검토→매수 체결→목표가 매도와 월평균 1,000만 원의 자금 조건은 [구조·자금 계획](capital-and-system-design.md)에서 먼저 읽는다. 프롬프트 원본 4개는 보존하고 최적화된 판정 템플릿·분석 재사용 계약을 로드맵에 추가했다.

백테스트를 실행하려면 [백테스트부터 자동매매까지의 실행 안내](backtesting-to-live-guide.md)를 읽는다. 3개 전략군·6개 후보, 환경 확인, 합성 데이터 실행, PostgreSQL 추출, 비용·지연·연도별 평가 명령과 결과 해석을 연결했다. 첨부 예제는 단일종목의 분수 단위 연구 모형이며 아래 기존 공동 계좌 실험 명세 전체를 구현한 것은 아니다.

## 진행 순서와 결과물

사용자는 2026-09-10에 아래 네 작업을 모두 승인했다. 순서는 **1 → 2·4 → 3**이다. 먼저 조건의 표현 범위를 정하고, 데이터 점검 결과를 백필 인수 기준에 반영한 뒤 실험 명세를 작성한다.

| 순서 | 작업과 목적 | 결과물 | 상태 |
| --- | --- | --- | --- |

| 2 | 홈서버의 시장 구분·가격·기간·이력 점검 | [데이터 점검](data-audit.md), `evidence/` | 읽기 전용 실측 완료 |
| 4 | 다른 프로젝트의 백필 결과를 인수할 기준 설정 | [백필 인수 기준](backfill-contract.md), `sql/` | 기준·재실행 SQL 작성 및 현 DB 실행 완료 |

## 현재 판단과 후속 작업

**9월 12일 22시 후속:** [가격 원인 추적](price-provenance-review-2026-09-12.md)에서 현재 배포 변환·저장 코드와 새 `data_vendor` 컬럼을 확인했다. 0원 1,201행은 유지되며 원천 부재로 원인 미확정이다. [HTS 대조 준비](hts-comparison-ready-2026-09-12.md)의 3종목 180봉 독립 검산은 완료했고 실제 HTS 검색 결과는 미확보다. 다음 작업은 원천·백필 실행 기록 확보와 HTS 동일 기준일 대조다.

**최신 재점검:** [9월 12일 백필 검토](backfill-review-2026-09-12.md)에서 8,202,637행과 2015-01-02 시작을 확인했다. 종가 0인 1,201행이 발견되어 현재 테이블 그대로의 수익률 실행은 `BLOCKED`다. 아래 수치는 보존한 9월 10일 기준선이다.

- 2026-09-10 실측 KRX 일봉은 4,481,979행·4,505종목이다. 1,804종목이 2023-05-11부터 812행만 보유하여 시작 구간 복원이 필요하다.
- 시장 코드 0에는 ETF 등이 섞여 있다. 현재 시장 분류만으로 과거 코스피 보통주를 재현할 수 없다.
- OHLC 관계·중복·음수 거래량 검사는 통과했고, API와 DB의 삼성전자 7일 값이 일치했다. 이는 가격 조정과 생존편향 해결까지 뜻하지 않는다.
- 다른 프로젝트에는 백필 인수 기준을 전달할 수 있다. 여기서는 가격 의미 확인과 HTS 단일 조건 대조 후 구현 단계로 넘어간다.
- 연구 설계안의 보유기간·비용·비중은 명시적 기본값이며 수익성에 맞춰 선택한 값이 아니다. 사용자의 허용 낙폭은 미정이다.

조사에는 공식 자료 확인용 저비용 에이전트와 백필 계약 작성·검토용 에이전트를 사용했다. 본 에이전트가 서버 읽기 전용 실측과 문서 통합·검산을 담당했다. 근거의 전체 데이터 덤프 대신 집계와 7일 API 대조 표본을 저장했다.

## 읽는 순서

먼저 이 문서에서 전체 진행 상태를 확인한다. 조건 대응표는 무엇을 실험할 수 있는지, 데이터 점검은 현재 무엇을 믿을 수 있는지 설명한다. 백필 인수 기준은 부족한 데이터를 채우는 담당자에게 전달할 문서이며, 실험 명세는 구현자가 같은 결과를 재현할 수 있도록 매매와 평가 규칙을 정의한다.

## 범위와 판단 원칙

- 사용자의 확정 요구: 여러 전략군 비교, 키움 조건검색으로 설정 가능한 조건, 홈서버 일봉 사용, 2015-01-02부터 별도 백필.
- 연구 제안: KRX 일봉 마감 후 판단, 다음 거래일 주문, 공매도·레버리지 없는 공통 계좌 모형. 실험 숫자는 투자 권고나 최적값이 아니다.
- 원본 DB 변경·백필 실행·수집 POST·조건식 저장·실주문은 이 작업의 산출물이 아니다.
- 문서상 조건 지원, Python 정의 작성, HTS 결과 일치는 각각 별도 상태다. 실제 일치 확인 전에는 완전 호환으로 표시하지 않는다.
- 서버 계정·토큰·환경변수는 수집하지 않는다. 저장하는 증거는 스키마와 집계값 및 공개 API의 최소 표본이다.
- 장기 커버리지, 상장폐지 및 과거 시장 이력, 가격 조정 기준을 통과하기 전에는 전체 코스피의 성과를 주장하지 않는다.
