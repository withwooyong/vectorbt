# 미커밋 연구 산출물 보존·핸드오프·푸시 WBS

목적: 예정된 v3 백테스트 구현을 시작하기 전에 기존 연구 산출물과 최신 PostgreSQL 점검 결과를 Git에 보존한다. 현재 판단: 기존 HEAD와 원격 master는 일치하며, 미커밋 문서·증거가 남아 있다. 범위는 핸드오프·문서·증거·검증·커밋·푸시다. 새 백테스트 구현과 수익률 실행은 포함하지 않는다.

진행률: **80% · 3/4 완료**. 남은 작업: 커밋·푸시와 원격 대조. 차단 없음.

## 판단과 검증 기록

- 사용자가 이번 메시지에서 커밋·푸시를 명시적으로 요청했다. 같은 행동의 재승인은 요청하지 않는다.
- 첫 fetch 후 `HEAD...origin/master`는 `0 0`, HEAD는 `6f99ae3`이었다.
- 루트 `.tmp_*.html` 5개는 삭제하지 않고 커밋에서 제외한다. 숨기기 위한 ignore 변경도 하지 않는다.
- 원본 감사 증거의 해시를 보존하며 과거 관측을 최신 확인으로 바꾸지 않는다. 오래된 현재 판단은 최신 핸드오프 우선 안내로 구분한다.
- Orca 워크트리·터미널 이관 없이 현재 저장소의 문서 핸드오프를 갱신한다.
- Git 바이트 보존: Windows `core.autocrlf=true`로 증거가 변환되지 않도록 7개 증거 경로에 `-text`를 적용했다. 원본 로그 공백과 Matplotlib 생성 SVG 공백은 해당 경로만 `-whitespace`로 보존하고 일반 문서·코드는 정상 검사한다. 원본을 고쳐 해시를 재작성하지 않았다.
- 검증: 신규 감사 도구 테스트 17개 통과(0.30초), `verify_evidence.py`와 `verify_discovery.py`의 저장 증거 검증 통과. JSON 42개 파싱, staged 증거 101개 원본 바이트 일치, 영수증 해시 81개 대조 통과. 두 외부 저장소 절대 경로는 현재 로컬에 존재하지만 다른 컴퓨터에는 별도 저장소가 필요하다.
- 독립 검토: 증거 줄바꿈과 구 업종 차단 문구를 수정한 뒤 중요 미해결 사항 없음. staged diff 및 `git diff --cached --check` 통과. 원본 증거의 공백을 일반 소스 오류로 처리하지 않는 예외를 위 Git 속성으로 명시했다.
- 이번에는 제품 코드 변경이 없어 전체 라이브러리·Rust 테스트와 MkDocs 빌드를 실행하지 않았다. Tests 워크플로는 PR/수동 실행용이며 master 직접 push만으로 테스트 실행을 주장하지 않는다.
